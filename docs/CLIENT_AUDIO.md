# 客户端音效

## 声音解析与播放

`ResourceCache`先读当前版本的`SoundList.lst`覆盖，再使用声音编号的标准文件名：普通编号为`000-0`，20000以上为`M0-0`。依次查找WAV/MP3，沿用版本清单与服务端大小写无关文件查找。只依赖438条覆盖记录曾导致大量现有怪物/技能声音没有加载。

声音使用独立的2路下载并发、有界128项流缓存和缺失负缓存，不被地图图片下载队列阻塞。切换版本会作废旧预热任务。现有专用音源优先，确实缺失时才使用`OriginalSoundRules.Fallback`中的已有同类声音；不会修改资源包或伪造文件。部分原怪物本来没有死亡等专用声音，仍允许无声，完整缺源见审计JSON。

WAV按RIFF声明长度截掉尾部填充后交给Godot解码，避免将素材尾部填充误读为音频块。磁盘原文件、网络缓存和Lib不改。23个现有文件包含尾填充；2379个声音文件全量解码通过，仍有16条Godot“Reading less data than requested”元数据读取警告，不能描述为音频日志零警告。

音效与音乐分别维护播放代次，切音乐不丢战斗声。音效24路混音、-3dB基础音量及-1dB硬限幅，音乐-18dB；设置总音量仍统一生效。同类声音45ms内去重，下载超过1.5秒的过时音效不集中补播，静音后不补播旧请求。

## 已接通的事件

- 怪物近战1–5、远程1–3、受击、死亡、出现，以及原特定动作帧、脚步、多段声音；守卫箭矢与宠物专用编号分别处理。
- 玩家武器挥击、命中、男女近战技能、双连斩第二刀、技能起手/弹道/命中、护盾与持续地面效果；声音按动作时刻触发，不等图片整段下载。走跑脚步随实际移动动画时长调整。
- 物品拾取、金币、使用、丢弃、出售、穿脱、合堆、仓库、交易、修理与学技等按成功回执播放；最后一件物品在状态归约前保留类型供声音判断，拒绝不播放成功音。

角色动作1.1倍速只同步动作相关发声时点，不改变声音采样率或音高。伤害、物品/金币变更和状态效果仍由服务端确认。

## 验证

```sh
dotnet run --project tests/Compatibility/Compatibility.csproj -c Release -- --audio-checks
# 创建临时版本、独立端口/缓存，包含全量解码、实际混音和原TCP道具/施法
bash tests/Compatibility/audio.sh
```

追加`--audio-report /path/report.json`可只读审计当前版本。当前覆盖494个有素材库的怪物、2528个引用声音编号，其中2440个有直接音源或明确替代，88个没有音源，均为怪物死亡声。审计与客户端一致查找WAV/MP3（例如`109.wav`缺失时使用`109.mp3`），不把不存在的攻击动作算作应有声音。

`default` 的导入素材和现用声音目录文件名一致；两处都没有`078-0`。新召唤骷髅沿用`078-5`，已在场的骷髅进入视野时保持安静；静态树木、大蘑菇和守卫也不再触发无音源的出场声。栗树、乌木和樱桃树的死亡声缺件时使用木箱破裂声`332-3.wav`，大蘑菇用植物死亡声`352-3.wav`。这些是替代，安装对应的原音源后优先播放原音源。编号`13.wav`至`16.wav`已用于脚步，不能当作`013-0`至`016-0`使用。

2026-11-18完整解码2379文件、20个代表声非零PCM、静音恢复、音乐并发、8声混合限幅及原TCP穿脱/用药/丢弃/拾回数量/火球三段通过。最后的动作节奏修改后仅复测20声真实混音及同一原TCP链路，均通过，没有重复全量解码。一轮中音频设备未输出采样（frames=0）失败，后续关键复测采样与播放成功，未将失败算通过。

怪物各动作的路由另用原协议包注入检查；这不等于全部494种怪物逐只实战试听。尚未覆盖所有设备输出、多人长时间混音或每个技能的人工听感。
