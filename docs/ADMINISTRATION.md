# macOS 运行与操作

部署后的目录布局、版本配置与复制操作见 [发布部署说明](DEPLOYMENT.md)。以下根脚本说明用于开发启动；默认数据为 data/versions/default。

## 环境

- .NET 8 SDK，包含 .NET / ASP.NET Core 8 运行时。
- Godot 4.7.2 .NET（mono）版。脚本查找 PATH 中的 `godot` 或 `/Applications/Godot_mono.app/Contents/MacOS/Godot`，其他路径使用 `GODOT_BIN`。
- 管理端的 MudBlazor 包随 .NET 构建恢复；不需要 Node/npm 来运行三端。集成测试另外使用 Python 3。

## 参考数据和迁移

首次运行需要：

```text
data/versions/default/import/
  Crystal Database/
    Server.MirDB
    Configs/
    Envir/
    Maps/
  Crystal Client/
    Data/
    Map/
    Sound/
```

已有本地目录已迁移：`Data/ref` → `data/versions/default/import`，`Data/runtime/server` → `data/versions/default/world`；SQLite 保留在 `data/versions/default/runtime/mir2.sqlite3`。旧预览图和历史本地构建产物保留在导入归档，不是在线资源。

服务端首次生成 `data/versions/default/assets` 并合并地图：服务端同名地图优先，其余客户端独有地图补入。源目录仍保留以便核对；不会再次覆盖当前资源、配置或 SQLite。初始化后，正常运行只依赖 assets、world、runtime，不依赖旧参考目录。

本机导入报告记录了 12 张冲突地图，包括 0.map、2.map 等；现在引擎与客户端直接使用 assets/maps 下的同一份文件。不要再分别维护两个 Map 目录。

完整参考世界加载约 463 张地图，占用数 GB 内存。首次资源导入、内容校验和世界加载需要等待，看到 `Game server ready` 后再登录。

## 三个入口

```bash
./start-server.sh
./start-client.sh
./start-admin.sh
```

分别在三个终端运行。再次执行同一入口，会构建、确认旧进程归属、正常停止并重启，不需要手动查 PID。只替换同项目和同运行目录的实例；无关进程和其他测试运行目录不受影响。构建失败保留旧实例。服务端 TERM 会保存，等待超过 60 秒才强杀。

默认游戏 TCP 7000、HTTP 资源/管理 API 5080、管理台 5081。管理台默认地址为 `http://127.0.0.1:5081`；start-*.sh 的 Debug/Development 本机免密，Release 输入 `data/versions/default/runtime/admin.key` 中的密钥登录。该文件和运行目录限当前用户访问；不要提交管理密钥到 Git。

```bash
# 从系统 /Data/ref 导入，但运行数据仍统一写入项目 data
MIR2_IMPORT_ROOT=/Data/ref ./start-server.sh

# 一套独立的数据目录与端口，三个入口应使用相同的数据/运行目录
MIR2_DATA_ROOT=/absolute/path/to/data MIR2_GAME_PORT=17000 MIR2_RESOURCE_PORT=15080 ./start-server.sh
MIR2_DATA_ROOT=/absolute/path/to/data MIR2_SERVER=http://127.0.0.1:15080 ./start-client.sh
MIR2_DATA_ROOT=/absolute/path/to/data MIR2_SERVER=http://127.0.0.1:15080 MIR2_ADMIN_PORT=15081 ./start-admin.sh

# 客户端 Godot 参数；-- 之后是游戏用户参数
./start-client.sh -- --server=http://127.0.0.1:5080
```

`MIR2_RUNTIME_ROOT` 可单独指定 SQLite、密钥、备份和进程记录位置；三个入口需保持一致。`MIR2_ADMIN_KEY` 可替代自动密钥文件，至少 32 个字符，后端和管理台需使用同一值。`MIR2_BIND_ADDRESS` 可改变游戏/资源监听 IP，管理 UI 仍只监听本机。

## 微端缓存与资源更新

Godot 客户端不包含游戏 `.Lib`、地图或声音目录，使用原素材编号、地图解析器和动画帧。它从 HTTP 清单取得游戏端口和资源版本，直接走原二进制 TCP 游戏协议。

下载并发为 8；响应和本地缓存均校验 SHA-256，网络文件先暂存再原子替换，地图/图片尺寸和下载长度有边界检查。默认缓存为 Godot `user://cache`，本机为 `~/Library/Application Support/CrystalMir2/cache`，可用 `MIR2_CLIENT_CACHE` 指定。缓存只是副本，不应在客户端修改素材。

“资源管理”支持全部/素材库/地图/声音类型筛选、路径搜索和下载。素材预览在弹窗内每页显示 20 张帧图片，按可用宽度排列为瀑布流，不显示动画 JSON。地图弹窗显示按原素材渲染的缩略图；“重新生成缩略图”重新渲染并刷新，保持长宽比，最长边为 1024 像素，不改写 .map 文件或玩家存档。生成结果仅作可重建的内存缓存。

页面已移除暂存、替换、撤销及发布入口，已有暂存文件不会被删除。受保护的暂存/发布 API 继续保留，发布会保存并重启引擎、更新资源版本；旧资源 URL 返回 410，失败恢复文件，备份位于 runtime/backups。不要直接替换运行中的在线素材。

## 游玩操作

- 登录页注册、登录；选角页创建战士、法师、道士并进入游戏。
- 左键地面绕障行走，远处右键先走再跑，近处（两格内）右键原地转身；左键怪物接近自动近战，Shift+左键/空格指定方向攻击。
- 左键地上物品走过去拾取，G 拾取脚下物品；左键尸体采集。
- I 打开背包；双击使用/穿戴，拖动换格，数字 1–6 使用快捷栏。C 打开角色，点击装备卸下。
- K 打开技能；绑定 F1–F12，保留原 Shift+F1–F8，绑定随角色保存。底部6格物品和12格技能使用相同正方形格子，点击技能格施放并显示冷却遮罩/秒数；聊天拖高时一起上移。
- 游戏菜单的“攻击模式”二级菜单切换和平、组队、行会、夫妻、师徒、敌对行会、红名与灰名、全体，以原TCP回执更新选中状态。夫妻/师徒模式保护实际关系及宠物，保留安全区和地图限制；新增模式需配套服务端声明支持。
- 左键 NPC 对话，链接进入商店、仓库等原脚本页面；购买、双击出售一件，修理页点击装备修理。
- Q 打开任务日志；NPC 的“任务”按钮接交任务。任选奖励必须先选一项；放弃任务需确认。背包标题“任务物品”打开独立物品栏。
- 仓库首次设密、每次重新解锁，可修改密码。双击背包存入，双击仓库取回，拖动跨窗存取/交换；同账号角色共享。扩展仓库沿用原服租期，`@ADDSTORAGE` 沿用原服开通命令。
- P 打开原版组队面板：开关组队、邀请/拒绝、队长移除成员；悬停成员看地图，`!!内容` 发队聊。关闭组队会退出当前队伍，队长离队后由原引擎维护队伍。
- T 打开原版交易双面板；先允许邀请，双方相邻并近处右键转身面对对方。双击背包/拖到报价栏放入物品，双击报价/拖回背包取回，点击己方金币追加；核对报价后双方确认。报价变化会撤销双方确认，Esc/关闭或掉线取消并退回。背包满/负重超限的退回物品及超过金币上限的退款进入原邮件系统（Godot 邮件界面尚未接入）。
- H 打开原版行会面板：允许邀请、同意/拒绝、公告和成员、职位调整、招收/移除、离会；有权限时可编辑公告、职位名称及八项权限，`!~内容` 发会聊。公告编辑时离开页签/关闭会保护草稿，收到其他成员的新公告后须放弃草稿并读取最新内容。离会仍受会长/战争规则约束。
- Enter 聊天；Esc 停止目标操作、关闭 NPC/任务/仓库。HUD 菜单支持拾取、回城复活、选角和退出。

账号 3–15 位、密码 5–15 位，均为英文字母或数字；角色名 3–15 位中文、字母、数字或下划线。过快重新连接时有原服同 IP 间隔限制，等待约 5 秒再连接。

## 管理与调试

监控每 3 秒读取原引擎的安全快照。管理端“重启游戏”只重启引擎，HTTP 宿主和管理台继续运行；根启动脚本则替换整个相应进程。

脚本/配置编辑器读取并提交版本，保存前备份，冲突时需重新读取。文件有未保存修改时，切换文件会要求保存或明确放弃，重载/重启按钮暂时禁用；两个开发标签保留编辑状态。NPC 和掉落脚本可以重载；任务脚本和配置修改需要重启。

“游戏数据库”切换类型会自动加载对应目录，可编辑：

- 物品/怪物：名称、等级、HP/DC、价格、堆叠、经验等基础字段。
- 地图：标题、资源名、光照、音乐和禁止战斗/传送/掉落规则；切换资源时需保持地图尺寸。
- NPC：名称、地图编号、可行走坐标、脚本、外观和交易倍率；可直接跳转关联脚本。
- 任务：分组、脚本、等级、允许职业、前置任务、类型和时限；拒绝不存在或成环的前置关系。

保存定义前检查读取版本，过期提交不会覆盖其他编辑；先独立备份，再写入 SQLite 并重启游戏。备份位于 `runtime/backups/definitions-*/Server.MirDB`，只包含世界定义，不包含账号和角色，不应替代完整 SQLite 备份。浏览器中断不会取消已经开始的保存和后续重启。

物品和怪物支持“复制为新定义”，需提供唯一名称。复制保留源定义的外观与规则，按实际最大编号分配 ID；新物品不会自动发给新角色，怪物沿用源掉落脚本且不会自动加入刷怪点。刷怪和 NPC 增改删分别使用“刷怪管理”和“NPC管理”；地图/任务新建、物品/怪物定义删除和地形素材绘制尚未提供。

## 保存、备份、验证

原配置 SaveDelay 控制自动保存；也可管理台立即保存或正常 TERM/Ctrl+C 停止。正常停止后备份 assets、world、runtime。SQLite 为 WAL 模式，不应在运行中只复制主文件；常规保存逐快照保留上一版；新运营操作的世界/玩家/行会联合事务和 SQLite Backup API 完整备份另见运营管理说明。

```bash
dotnet build Mir2.sln -c Release
MIR2_DATA_ROOT="$PWD/data/versions/default" dotnet run --project tests/Compatibility/Compatibility.csproj
dotnet run --project tests/ItemSecurity/ItemSecurity.csproj -c Release
./tests/Compatibility/smoke.sh
./tests/Management/smoke.sh
./tests/Management/administration.sh
```

测试使用临时世界及 SQLite，素材库只读复用。真实 Godot 覆盖战斗、升级、地图、任务、仓库、换角和重启存档；重启检查包含物品名称/编号/数量，且故意破坏地图缓存来验证重新下载。管理测试覆盖五类定义编辑/冲突、复制分配、坐标/路径/前置校验、写入失败撤回、发布失败恢复、鉴权和三端启动替换。测试不修改正式世界。

仍未完整移植交易、公会、英雄、拍卖和全部技能/特殊特效。未验证 Intel Mac、多人压力、长期运行或签名/公证的 `.app` 导出；原参考资料的 HiGreatGhoul 掉落警告仍保留。

地图运营编辑器使用统一资源库生成缩略图和精确碰撞位图，Godot 与管理端共用地图素材索引表。“刷怪管理”支持多点独立参数和整批事务，点击标记或列表管理会打开弹窗并显示所选怪物形象。地图内的阻挡格也可布点：引擎先将阻挡中心调整到最近可行走格（格子坐标的平方距离，同距按既有可行走格顺序），再按设置范围选取出生点；原布点坐标保留，热更新与重启加载共用该逻辑。地图外坐标仍被拒绝，全图无可行走格时不生成怪物。新增点的弹窗可“继续地图布点”保留草稿，再一次提交全部点。“NPC管理”使用原始 1:1 比例，每格 48×32 像素；视口按需读取 1024×1024 地图块，已有 NPC 按原图尺寸和偏移显示。右上角小地图点击或方向键快速定位，Home 回到左上；鼠标移入大地图显示格子坐标。点击 NPC 或列表“管理”打开弹窗，点击可行走空地新建。

运营视图显示静态地形和 NPC 站立首帧，不模拟天气、光照、NPC 动画或玩家移动。地图块、资源缩略图共用有界缓存，旧地图版本请求被拒绝，错误可重试；资源仍来自所选服务端版本。

NPC 弹窗的“属性”页保留名称、坐标、外观和可见条件，显示同编号原素材形象；“脚本”页自动读取 Envir/NPCs 下对应 TXT，可编辑、备份保存并重载。缺失脚本在保存时自动创建，读取和取消不会创建文件；新 NPC 保存属性时会先保存缺失/已编辑脚本。脚本文件和 NPC 属性分两步保存，属性校验失败时已保存的脚本仍保留，并在弹窗显示结果。未保存编辑关闭前需明确放弃，更换脚本路径保持安全重启。

交易托管存档升级至自定义版本 2，旧 0/1 版本仍可读取；首次升级由宿主自动备份 SQLite。不要用旧服务端打开升级后的运行库。异常退出恢复以最近一次成功保存的整个玩家快照为准；未保存进度仍可能回退，尚无逐笔交易日志或每笔成交强制刷盘。

当前行会范围包含信息、公告、成员、职位、邀请/离会及仓库/资金闭环；增益、联盟/战争、领地和原 NPC 新建行会弹窗尚未接入 Godot。可在管理台创建行会，再由玩家按原协议招收成员。公告协议没有版本条件提交，客户端可检测已收到的外部更新，不能保证两个同时到达的保存请求互不覆盖。

## Godot 行会

行会面板复用原 `Prguse` 180、1850 和 `Title` 25/93/99/101 等素材，以原 GuildStatus、GuildNoticeChange、GuildMemberChange 和 GuildInvite 驱动。公告/成员变更标记触发最多每秒一次的按需请求；完整列表到达后停止请求，在线/离线增量直接更新列表。换角、退会、断线清除行会数据；行会身份、公告随原账户与行会快照保存。

公告上限 200 行/20000 字符由 Shared 常量统一给原引擎、Godot 和管理端使用；权限判断由引擎执行。客户端保存前比较已读取的公告基线，收到外部更新保留草稿并要求读取最新内容；原协议没有 compare-and-swap，仍可能发生尚未送达客户端的并发覆盖。保存等待超时会保留草稿以便重试。

服务端修复普通职位越级修改成员、负权限位、重复关闭权限反向启用和非成员修改职位名称；权限变化主动刷新受影响玩家状态。邀请接受重新检查已有归属、邀请开关、行会存在性/容量/战争，原可信 NPC 加入行会仍保留专用入口。离线成员移除同步清除角色行会编号。管理监控读取同一游戏线程的行会与职位。

测试使用附带独立行会和离线会长账户的专用 fixture；正常世界不启用测试权限。真实 Godot 验证入会/拒绝、公告权限/传播、成员与职位、会聊、重复权限关闭、移除/离会/再加入、离线状态、仓库/资金及重启后的身份和资产。增益和战争/领地留待后续闭环。

Godot 的行会仓库页支持安全区内按职位权限存取/交换及成员捐献、会长取款。管理台仓库保持只读，资金和格位直接读取同一引擎数据；存档编辑仍要求相关账户离线。账户与行会在同一 SQLite 事务保存，失败一起回滚；未保存的操作仍可能在异常退出后回退。

在线玩家表新增所属行会与职位，来源仍为原引擎对象。Godot 现可依职位权限维护公告、招收/移除和调整成员及职位；管理台存档编辑仍要求相关账户离线，避免与游戏内操作相互覆盖。原游戏协议公告限制与管理端共用 200 行/20000 字符的上限。


## 当前交互与缓存规则（2026-11-11）

所有管理列表使用表格；创建/编辑使用统一紧凑弹窗，保存按钮在右下且先确认，右上角关闭，无操作按钮时隐藏底栏。删除、软删除、移除成员和解散均确认；取消保存不提交、取消关闭保留草稿。账户仅允许删除离线空账户，不级联清理角色（含软删除）、资产、拍卖或仓库权益；操作失败保留原数据和完整备份。

操作审计页面、导航、API、请求字段和写入均已移除，无需填写操作原因。服务端下次打开 SQLite 会删除旧 admin_audit 表及其记录；原有完整备份保持原样。表单也不再要求手工输入“确认目标”，目标原名称从已读取对象自动传入服务端校验；保存/删除确认弹窗、版本冲突检查、在线保护和事务回滚继续生效。

NPC 创建入口仅保留大地图可行走空地点击，页面“新增 NPC”按钮已移除。新名称自动补全脚本路径，中文转无声调小写拼音；手工路径或已编辑脚本不随名称覆盖，多音字可手动校正。已存在 TXT 会明确提示并加载；不主动编辑时只关联现有脚本，读取和取消不创建文件。NPC/刷怪地图下拉可按代码、编号、名称及空格分隔的关键词搜索，展示代码（#编号）、真实格数、名称与数量，怪物区分存活/配置/刷怪点。

规范缩略图由原地图和素材按每格 48×32 像素渲染，等比且最长边 1024。持久缓存位于所选版本 runtime/cache/map-thumbnails/<素材版本>，只保留当前素材版本，PNG 与校验值通过临时文件替换。损坏可重建，重新生成覆盖同一地图缓存；资源预览、NPC/刷怪小地图和 Godot 读取同一份 PNG，管理地图与客户端每 5 秒检查内容修订值，旧修订请求返回 410。源地图、mmap.Lib 和 SQLite 不变；缺少原素材时仍显示缺失说明。

微端窗口按屏幕缩放与可用像素区域适配，保持 1024×768 逻辑画布和 4:3 比例；手动调整窗口不被周期性重置，换屏或 DPI 改变时重新适配。本机 2× Retina 实窗记录为可用 3600×2260、窗口 2560×1920；尚未验证 Windows/Linux 实机和多显示器切换。

刷新地图旁的“怪物列表”/“NPC列表”打开全局图鉴，支持名称/编号搜索，服务端每页返回 50 条。怪物左侧名称及原形象、右侧原引擎属性按 4:6 分栏，中间有明显分割线；属性为双组“属性/值”表格。刷怪新增和管理复用同一表单及形象预览，主按钮分别为“创建刷怪点”与“保存刷怪点”；“怪物定义编号”右侧的“查找怪物”打开同一图鉴，选择后立即关闭并回填编号和形象。单点直接创建，也可继续地图布点后整批保存。地图名称使用紧凑字距和不随缩放放大的细描边，保持字体比例。

NPC 按自适应瀑布流展示名称、原形象、地图/坐标/脚本等信息；每张卡片右上角的“查看”关闭列表，通过现有 NPC 详情接口读取所属地图编号，再切换并将原尺寸大地图定位到该 NPC。当前地图内的不同 NPC 或重复查看同一 NPC 也会重新定位；NPC 已删除、地图缺失或读取失败时显示错误。资源地图预览增加对应游戏地图名称/代码/编号、图号、音乐/光照、NPC/刷怪点、原始像素、文件大小/修改时间与阻挡占比；同一资源关联多张游戏地图时逐项列出。INI 读取不再建目录，只有保存才创建父目录。
