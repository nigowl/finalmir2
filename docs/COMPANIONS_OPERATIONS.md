# 陪玩系统：管理与运行

当前实现日期：2026-11-27。管理入口为左侧“陪玩管理”（`/companions`）。所有操作绑定管理端显示的版本；首次运行总开关关闭，默认不创建角色、不启用 LLM 或 PK。

角色详情“最近运行事件”显示本次会话最近50条事件，其中“LLM日志”区分真实调用中、已返回、无效返回、调用失败和未调用，并记录待执行、已采用和未采用。实际调用记录所选模型、耗时及通过短文本校验的返回；失败仅显示HTTP状态、超时或格式等安全原因，不记录密钥、接口地址或原始供应商响应。并发、调用间隔、未配置和每日额度阻断都有明确原因；“已采用”表示实际发出对应移动/战斗/聊天请求，不代表游戏资产操作或任务完成，离线/重启后不保留会话事件。

## 启用与日常管理

1. 构建服务端会同时生成 `companion/` 执行组件；发布脚本将其打包在 `build/server/companion`，无需另外启动。运行中的旧服务端/管理端须正常保存退出后配套更新，不能覆盖活跃程序；default的实际更新与观察结果以`COMPANIONS_LIVE_TEST.md`为准。
2. 打开“陪玩设置”，启用本版本总开关，设置陪玩在线数与真人预留数量。原服 `MaxUser`、`MaxIP`、封禁、注册频率和登录开关继续生效；调大陪玩在线数不能绕过原服限制。列表显示排队原因及实际限制值；原服总人数和同IP限制在左侧“系统设置”调整，保存后自动重新排队，无需重启。10个陪玩加1个本机真人时，MaxIP至少设为12（另预留1个本机名额）；见[系统设置](SYSTEM_SETTINGS.md)。
3. 新增陪玩：填写原规则允许的昵称、职业、性别，选择人格及作息。保存只登记档案；启动后通过原 TCP 注册随机普通账户、建角、登录，不使用 GM 发物品或传送。
4. “启动”清除该角色错误及人工下线抑制；“暂停”保留连接和药品保护、暂停发展；“继续”恢复发展；“下线”正常退出并抑制当前窗口。到达会话/每日额度时自动下线，休息后再按日程排队。
5. 列表左侧勾选角色后使用“批量上线 / 批量下线”，表头只选择当前页，跨页选择保留并显示数量，可一键清除。批量上线仅启用并提交所选角色的上线意愿，不改变总开关，不清除历史用量、休息和死亡预算；存在错误或死亡预算保护时整批拒绝，须先逐个核对。批量下线沿用当前窗口内不重连和正常退出规则，不关闭总开关或影响未选角色。提交冻结的编号及读取版本，任一目标已修改、缺失或写入失败则整批撤回。仍遵守日程、配额、人数、MaxIP与注册频率。
6. “详情”查看账户/角色编号、原因、用量、实时生命/魔力/金币/经验、目标坐标、任务计数、未来七天时段和最近50条运行事件；事件按角色时区以时间/事件/状态/说明表格显示，地图同时显示实时坐标，详情每5秒刷新。在线角色同时显示原引擎物攻/魔攻/道术、防御/魔防、准确/敏捷/攻速，已学技能的原0–3级和当前/所需熟练度，可展开全部非零属性；只复制游戏线程当前值，不在界面重算。真实背包、装备和任务继续在“角色管理”查看，不维护第二份资产模型；离线角色不伪造实时战斗属性。
7. 需要停止整个版本时，在“陪玩设置”关闭总开关。“解除托管”要求会话已完全离线，只删除陪玩登记，保留原账户、角色和资产。身份绑定后不能在陪玩编辑器改昵称/职业/性别；管理别名随时可编辑。

保存、归档、解除及批量上线/下线使用现有确认弹窗；表单取消不写入，未保存关闭有保护。资料保存采用读取版本检查、完整 SQLite 备份、事务与失败撤回，冲突不会静默覆盖。

总览“在线”与列表在线筛选统一按原服绑定角色是否实际在线统计；连接中或已经断开的执行会话不计入在线人数。调度名额仍按未清理会话预留，避免并发登录超额；重启后按原登录节流逐个恢复，符合日程但超过当前上限的角色正常候位。恢复时间已到但尚未进入日程的托管角色继续等待，不因旧故障记录强制提前上线。

## 批量新增

“批量新增陪玩”支持一次1–100个，当前版本总档案上限500个。默认内置1000个合法且不重复的中文昵称，如“下班才上线”“菜但爱玩”“装备全靠捡”“欧气借我点”；批量新增直接使用“昵称管理”预设池，不在此弹窗编辑候选名，支持随机职业、性别、人格，也能指定统一值、标签及日程。默认只创建离线档案，LLM关闭。

先“随机生成预览”，再确认保存。生成时无放回随机选择昵称，过滤原角色/陪玩重名、候选重复和不合法名字；不足明确报错。改数量或参数后须重新预览。预览不写入，取消不保存；确认后全部档案与昵称池在同一事务保存，任一项失败全部撤回。网络重试保留预览编号，不重复创建；昵称池随当前版本SQLite保留。实际TCP注册不是数据库原子事务，由调度遵守原服限制逐个执行。

所选工具栏按“批量日程设置 / 批量上线 / 批量下线 / 批量LLM设置”排列，不放在页面顶栏。批量LLM可统一关闭、社交增强或社交与候选目标建议，并选择已启用模型或版本默认模型；关闭保留各角色原模型指定。只修改所选角色LLM字段，保留日程、启停、历史用量和错误保护；版本冲突或无效模型整批拒绝，不发送模型测试或清空额度。

## 昵称管理

“陪玩设置 → 昵称管理”独立维护当前版本候选池，可搜索、分页、查看已使用状态、单项移除、批量录入及补齐到1000个。补齐保留已有昵称及顺序，不更改现有角色姓名；旧版本已保存的昵称池不被启动过程覆盖。所有修改先进入设置草稿，外层确认保存才写入 SQLite，取消不写入；昵称仍按原角色命名规则校验，空行与重复项合并。

## 人格与作息

随机新增与智能轮换入口已合入“陪玩设置”，详见[调度说明](COMPANIONS_SCHEDULING.md)。随机新增默认关闭，间隔可自定义1分钟–1个月（固定30天），触发后才安排唯一下一次，默认每30–120分钟新增1名、最多100档案；所有计时随当前版本SQLite保存。智能轮换默认开启，以勤奋/坚持随机确定本次在线及休息时长，保留角色单次上限、日程及每日/滚动配额，等待较久者优先补位；列表可看候位序号/本次截止/休息结束。

提供随性、懒惰、勤奋、PK狂、热心队友、探索者、稳健、收藏者、节俭、社交、独行、竞技12种预制。人格标识及修订固定，角色保存解析后的十项数值；切换世界定义不会把原人格重新抽签。

勤奋影响短休息；风险影响试怪等级及撤退阈值；对抗影响约战接受；社交/助人影响组队及治疗；探索影响寻路和公开地图入口；节俭影响药品库存及支出预算；收集影响先拾物还是先追怪；坚持影响无进度重新查询的等待时长；健谈影响模板及发言间隔。人格不能提升权限。装备优先目前只影响换装与拾取，并非已实现完整掉落收益预测。

自定义人格由内置复制或创建新修订；旧修订不可原地覆盖。归档只改变新建选择，已有角色保留引用与独立参数；可以恢复归档。

“人格管理”保留既有人格修订管理。“日程管理”提供预设新增、编辑与删除，默认8种北京时间预设：上班族（周一至五9–18）、未成年（18–21）、夜猫子（22–次日5）、晚间休闲、午休小憩、周末畅玩、早鸟和全天轮换。名称仅为时段示例，不代表身份或合规验证。

角色、批量新增及随机新增默认作息均可下拉选预设，自动复制全部参数后仍能手改，修改后显示“自定义”。预设是参数模板，之后修改或删除预设不会追改已保存角色。日程下拉增加“随机”：单角色编辑时随机填入一套并可手改；批量日程设置和批量新增时由服务端为每个角色独立抽取当前日程预设（允许重复），批量新增预览显示实际计划。随机新增默认作息也可选择随机，每次真正新增时抽一次。已分配角色只保存具体日程，刷新/重启/预设修改不重新抽取；没有预设时拒绝随机分配，不用默认参数静默替代。

列表“批量日程设置”只更新所选角色的日程/自动上线选项，保留启停、当前会话计划、历史用量和错误保护；新日程及每日/滚动配额继续参与资格检查，不强制开始新会话。

作息支持显式时区、每周多个窗口、跨午夜/全天、出勤概率、上线抖动、单次时长、休息及每日上限。预览只读。固定随机种子保证同一窗口不因刷新/重启重新抽出勤；处理夏令时缺失及重复时刻。没有离线补练。

在线时间以最多10秒的小块提前落入本版本 SQLite，重启不清零；当天和过去24小时都限制，可能保守少用约10秒，不能以重启规避。暂停仍计在线时长。轮换退场先等待未决资产/药卷/移动回执，未发退出请求或明确拒绝后仍复用原保命；退场面对最近真实攻击者即优先尝试原单步撤退，不等低血或打完可猎杀目标，无可行撤步才近身自卫，不再开展新发展操作；发原LogOut后等待原回执期间不插入动作，收到LogOutSuccess才关闭TCP，旧连接与组件均退出才释放名额。原服明确拒绝时等至少1秒再申请，仍遵守战斗保护；同一请求5秒回执未知停止且不重发，原30秒整体退场预算保留。尚未实现提前返回城镇或安全脱战的专用路线，持续围攻仍受限；宿主停服及故障清理仍走原路径。

## 游戏行为

正常退场时，只有仍处于最近怪物受击的原退出保护期或玩家追击期才继续主动自疗；安静后停止施放治愈术，避免每次施法刷新原LogTime而永远等不到退出。药卷保护、未决资产、近期遇袭自疗/撤退和30秒预算保持，发展或暂停期间仍正常自疗。此修复不保证完全封路或持续围攻下能安全退出。

| 行为 | 当前边界 |
| --- | --- |
| 移动与跨图 | 当前地图原 `.map`、SHA-256 校验及有界寻路；服务端按当前版本地图编号规划公开普通步行入口的首段路线，任务和练级均可跨图；探索优先保留独立探索偏好，不执行隐藏跳转 |
| 发育 | 服务端提供适合等级/风险的怪物刷新点及已加载活怪位置；陪玩走到目标区域后按原 TCP 可见对象打怪，基础普攻/已学单体法术、拾取、换装、学书、低血撤退及原回城复活 |
| 任务 | 服务端直接提供可接 NPC、本人进度及真实怪物掉落来源，支持走到视野外 NPC 接取、跨图击杀/收集、有限主对话标记、返回交付及选择首项奖励；不自动点击任意剧情脚本链接 |
| 补给 | 红药目标12–20份、非战士蓝药目标6–10份，随节俭程度变化；少于目标一半时提前返程，保留路上耗药余量。服务器按当前版本NPC商品、职业/等级、真实单价/税率、金币预算和负重规划公开可达商店；补给优先于猎杀/拾取。原 BUY/BUYSELL 与 REPAIR、串行资产回执继续生效；取下破损装备、修理、重新穿戴。负重达80%或空格≤2时，先出售符合保护规则的普通武器、重复衣服、普通肉及材料/食物余货；只需出售时也可进入原 BUYSELL 页面，不要求同时缺购买物资；减负会话不顺带采购商品 |
| 组队 | 自主邀请允许组队的陪玩，同行会/职业互补优先；原名单确认后沿公开出口跟随队长，协助合法交战目标及治疗真实低血队员；补给、筹资、交付和可进行的个人任务优先，不主动邀请真人 |
| 聊天 | 点名附近聊天、队聊或私聊的有限中文模板，无模型也工作；有发言间隔 |
| PK | 总开关默认关闭。仅自卫使用短时红褐模式；约战需附近玩家明确发出“角色名，切磋”或“角色名 切磋”，限30秒，排除队友/安全区/禁战地图并低血撤退；无目标时恢复和平模式 |
| 不确定结果 | 资产请求串行，匹配原回执；未知资产/移动结果或死亡预算超限停止并显示原因，不盲目重发；长期无进度改为待规划并保持在线 |

接取与交付只执行服务器当前明确安排的任务编号；附近已有可交任务也不能抢占减负、仓库或必要补给计划。满包被原服拒绝仍可能没有任务变更回执，不根据聊天文本擅自解锁或重发旧请求。

有击杀汇总说明的任务仍显示每个子项的真实数量，汇总文字不再遮住计数；微端和管理详情共用原TaskList。不同怪物定义可能具有相同显示名，具体来源按原怪物编号/名称前缀区分，显示进度不改变计数、奖励或完成状态。

标记任务仅支持当前已加载NPC主对话的一段脚本：单个`CHECKQUEST 当前任务 ACTIVE`条件，成功分支只`SET`该任务的一项标记为1、提示及`BREAK`，失败分支无动作，也没有跳转按钮。全部标记均有对本人可见、公开路线可达的此类来源才自动接取；已完成标记不再访问，暂不可达仍排除。服务器只读识别，不调用脚本条件求值/执行，也不改角色标记；执行组件复用现有service目标走路、原`CallNPC [@MAIN]`，由引擎更新真实任务进度。含扣款/物品/传送/其他条件、分支动作或任务外标记继续不支持；没有新私有字段、原TCP变动或持久模型。

服务器每3秒检查一次当前目标：减负、必要药卷和修理后，优先交付已完成任务；保留无武器恢复、低资金筹药及行会计划后，先访问受支持的已接任务标记，再接取已解锁且可执行的送物/拜访剧情，避免旧猎杀任务长期压住后续发展。此类优先任务必须没有击杀/掉落收集项、没有未知标记，并有经验/金币/物品奖励或被后续任务引用；已满足前置的剧情优先，原NPC身份、可见性、等级、职业、前置、任务容量及暂不可达检查不变，不自动删除旧任务。随后继续未完成击杀/收集，考虑其他有目标来源的可接任务，最后寻找有经验收益的适级怪物。多个未完成任务均先经过原战力、公开路线、禁战与暂不可达预检，优先当前地图，其次剩余击杀/收集总数量较少者；同分保留任务原顺序，不随活怪坐标浮动切换。此数量仅近似工作量，尚未按掉率或完整路径计算最短预计耗时；空闲练级另按下文的经验/耗时估值选择。收集任务按物品定义编号查询当前已加载 `MonsterInfo.Drops`，包括正概率的分组掉落；不靠昵称猜怪、不要求角色先亲自见过掉落。NPC、刷新点和公开入口均取自当前版本，不维护另一份世界配置。知识查询不代替接取、战斗、拾取、购买或交付，所有执行仍经过原 TCP 与服务端校验；无需启用 LLM。

药店选择先保留缺药优先于缺卷，再沿已允许的公开步行链比较跨图数，同数按该路线到店地图入口至NPC的格距排序；同图从本人当前位置计算，不再把所有跨图药店赋同一距离而按世界加载顺序选店。暂不可达、组队/洞口/条件/攻城限制、实际货架、原价/税率、本人身份、人格预算及容量检查保持。该近似不计中间地图走路、障碍或沿途伤害，也不改变原BFS选出的入口，不能保证整路耗时或总药费最优。

已完成任务安排交付前，服务器用不占真实物品编号的奖励样本复用原`CanGainItems`，按固定奖及各选择奖分支检查普通背包/任务背包容量，不提前扣任务物或假定交付后才空出的格子可用。当前执行组件自行选奖，因此保守要求每种选择都能放下；不改变原奖励/堆叠/领取权限。放不下先保留原减负和其他可行任务，没有其他工作时保持在线等待容量，腾格后再规划原交付；原未知回执保护不会自动解除。此预检不保证目标下发后背包变化与执行之间完全没有时序窗口。

减负处理普通多余武器、同一定义的普通重复衣服（Armour）、普通肉（Meat），以及普通材料/食物（CraftingMaterial/Food）的多余数量；材料/食物按物品编号跨堆叠至少保留5份，达到减负目标后不保证每类都恰为5份。衣服只在已有装备时处理背包重复件，每种定义保留当前耐久最好的一件；不同定义的唯一衣服不比较优劣、不出售，未知堆叠或最大耐久偏离定义的衣服也保留。服务器给出唯一编号及最多可售数量，执行组件再次计算，取双方允许数量的较小值并走原SellItem回执，不预扣库存。普通肉满包或达到负重线也主动规划支持肉类的可达商人，不必等碰到附近NPC；正常肉品质超过定义耐久仍有效，未知堆叠/特殊属性保留。明确减负会话只处理当前允许清单，没有允许项时停止出售，不能回退临时卖肉绕开全版本任务/配方保护。保留已装备物、一把当前可用备武器、升级/未来等级武器、全版本任务收集/携带物及已加载配方的材料/工具，并沿用绑定/租赁/附加属性/精炼/觉醒/镶嵌/稀有/工具等保护；原普通肉出售规则继续保留。不会自动丢弃或删除，其余非武器装备、矿石、药卷及受保护库存积压仍有限制；普通材料暂存边界见下文。管理详情显示真实负重上限及空格。

普通地面拾取预留20%负重及2个空格，当前必需任务物可按实际剩余容量处理；金币仍可在满包/超重时按原金币上限拾取。服务器按当前可见物品、归属及原CanGainItem/CanGainGold提供有界候选，原PickUp没有目标编号，因此只评估同格原顺序中真正会先拾取的一件，不跳过重物选择其下金币。执行组件入包后清空旧候选，等待下一次知识快照。非任务尸体采集同样在减负阈值以上暂缓，必要任务采集仍遵守原归属与格位。以上是自动决策保护，没有改变原玩家拾取规则，也不承诺并发抢拾/延迟下的硬性负重上限。

负重达减负线后，尸体是否属于必要任务采集由服务器按当前未完成的物品子项和此怪物的真实正概率掉落（含分组）判断；不能因同一任务尚缺另一物品，继续超储备割取已经收齐的材料。沿用已有Harvestable知识字段和原尸体归属/格位校验，未改变原Harvest包或引擎出货；真正必要采集仍可能同时获得普通副产物，不能据此保证背包始终不超重。已有受保护积压不会自动删除或出售。

背包达到80%负重或空格不超过2格时，先按当前版本公开路线前往NPC仓库暂存允许的闲置物品，再考虑出售。除原普通多余材料/食品和同定义重复备装外，允许暂存矿石、肉、已学或其他职业技能书、过量普通恢复药及不优于已穿装备的闲置装备；任务收集/携带物仍按全版本排除，不把普通背包和任务栏混用。只访问实际对话返回的STORAGE链接；条件未满足的NPC暂时排除。

新闲置装备筛选与执行组件共用原装备评分，按类型保留当前可用的最好1件备装，戒指/手镯留2件；已穿装备不参与，能提升当前装备或未来等级可用的装备保留。禁存、租赁、时效、封印、强化/改最大耐久、GM/诅咒、灵魂/婚戒等检查保持；原同定义普通重复备装筛选仍保留。恢复药按强度优先以整堆保留至少20份红/10份蓝，双恢复药参与相应储备；卷轴、符与必要照明不随新策略存入。全部走原唯一编号存仓，不丢弃、出售或重造。当前只自动取回基础材料，其他暂存物可手工取回，不宣称已有完整装备/药品仓库调度。

存入整叠后，已在原仓库会话内可在安全负重/空格内按物品编号取回至每种5份基础材料。单独为不足5份的普通材料返仓只在没有可进行或可接取任务时安排，不能抢占任务猎杀、收集和交付；这些材料没有当前任务用途，不因储备不足从远处折返。药品、修理和主动减负优先级不变。拆分按原SplitItem1源数量确认、SplitItem新唯一编号两段回执核对，再以原TakeBackItem取回；不合并伪造编号，不预扣，不超时重发。至少预留有效仓库的拆分格，只使用服务端当前已开通容量；满仓时保留资产并重新规划。仓库一默认80格，二至四各80格按当前版本配置任务逐级永久开通，同账户共用；原租用权限和已有资产保留。多个材料或其他受保护积压仍可能导致容量不足，不能保证每次都能取回5份或完成补给。

需要仓库密码而尚未设置时，通过原SetStoragePassword设置由该陪玩已有账户凭据派生的独立密码；不依赖目录或昵称、不新增浏览器密钥，完整复制版本仍可解锁。已有人工密码不猜测、不覆盖，原服拒绝后停止该陪玩并提示核对；不要求密码的版本按原规则直接存取，不强制设密。存取、解锁/设密与拆分均串行等待原服回执，未知或不一致时停止核对；切图、死亡、低血/遇袭或暂停会结束本地仓库动作，仍保留未决资产保护。此流程只操作绑定陪玩自己的账户仓库，不操作其他玩家或行会仓库。

账户统一改为`pw数字`时，只有原仓库凭据确实匹配旧账户的自动派生值，才与账户同事务迁移到新派生值；人工密码、登录密码和原密码设置时间保持，提交失败恢复原哈希与盐。已完成旧版改名的账户须先核对历史自动凭据、离线身份及资产，再通过原管理密码接口修复，不能猜测或覆盖人工密码。原解锁回执的正常成功和无密码成功均可继续存取，密码错误仍停止。

NPC购买收到原服系统消息`购买失败：…`，且当前串行请求尚未收到商品和扣款时，按明确拒绝暂时排除该目标；普通聊天、无关提示或只有商品/扣款一半的结果不能据此解锁。购买回执未知仍不重发，须重新登录核对权威金币、物品编号和数量后再恢复。原服已确认死亡时，普通红蓝药的明确拒绝保留死亡次数并继续原复活流程；卷轴拒绝、地图禁药及未知回执保护保持。

尚不自动操作玩家交易、行会资产、邮件领取、拍卖、锻造或任意复杂剧情；未知版本内容在“兼容与能力”中显示限制。这些内容仍由原引擎与人工管理处理。

目标快照通过私有管道送达，地图确认来自原TCP，两者可能乱序。执行组件保留最近快照，仅在其中的地图编号与原MapInformation/MapChanged匹配后启用；提前到达的新图信息不再被地图包清掉，迟到的旧图信息不参与目标、药品/回城及战斗判断。同图地图信息重发不丢有效快照，切图仍清理移动、NPC/仓库及地图素材状态。复用原地图编号，不按地图名/文件名猜版本，不增加重发资产或新的协议字段。

原任务脚本的奖励、携带/收集和击杀条目允许前后空格、多个空格或Tab分隔；未指定数量仍为1，纯空白行跳过。显式零、非法数字或溢出仍沿用原数量解析结果，不自动补成1。修复脚本空白解析需要正常保存重启，让当前版本重新加载任务；只影响后续接交，不重开已完成任务或自动补发历史缺奖。奖励生成、职业/性别、背包容量及资产提交仍由原引擎执行。

自动喝药与微端共用`ClientAutomation`：缺口较大时选有效恢复最多的一瓶，足以补齐时选浪费最少的一瓶，避免首格小药一直占用喝药机会。保留原使用间隔、串行回执、拒绝/超时保护，不预加生命/魔力。基础物资50%及等级/生命分档见[怪物管理](MONSTER_MANAGEMENT.md)，default掉落倍率1、经验10；这不代替多怪围攻、长途补给与长期死亡率验证，已有死亡/资产未知保护不自动解除。

## 行会与攻城

单个陪玩“管理 → 行会与攻城”及批量新增均可设置关闭、主动入会、自主建会或优先入会/条件建会，填写目标/拟建名称并独立勾选参与攻城。详情显示真实会籍和发展原因，事件显示申请/邀请与建会/入会回执。默认关闭；建会保留至少半数金币、必须满足当前版本真实等级/材料/NPC条件，入会走原邀请，攻城另需PK总开关与本会参战资格。原会籍不自动退出，行会资金/仓库不自动操作。操作步骤、推荐组会方法、兼容与实测范围见[行会发展说明](COMPANIONS_GUILDS.md)。

## 可选 LLM

模式为关闭、仅社交、社交/行会与候选决策。陪玩设置可以管理最多20个模型，每个模型独立设置显示名称、API地址、模型标识、密钥和启用状态，并选择默认模型。陪玩开启增强后可选择具体模型或使用本版本默认模型；稳定编号防止重命名时串用密钥。已被启用增强的角色显式引用时，移除模型会被拒绝；停用/不可用时回落规则。可用本地兼容服务，没有新增SDK依赖。

“模型设置 → 添加服务商模型”输入基础API地址或完整Chat Completions地址、密钥，点击“获取模型”读取兼容的`GET /models`列表，可筛选并一次多选导入；不支持列表时可手动补充模型标识。根地址补`/v1`，已有`/v1`或自定义基础路径保留；完整`/chat/completions`转换为同基础路径`/models`。同一服务商的多个模型仍保存为独立稳定编号，可分别选用与编辑。

获取列表不保存草稿、不扣本地推理额度，5秒总超时、512KiB响应、最多1000个模型，最多两个并发，同一地址5秒间隔；拒绝重定向，避免密钥转发。留空只能复用同一API地址已保存的密钥，换地址或额外导入模型时须重新输入密钥（也可明确清除）。错误不包含密钥或服务商响应正文。

模型设置、编辑弹窗和角色模型选择旁都有网络检查图标。测试发送一次真实短请求，验证地址、鉴权、模型和短文本JSON，显示成功/错误和耗时；使用当前输入但不保存模型草稿。测试计入本版本每日模型额度，最多2个并发，同模型5秒间隔；不向浏览器回传密钥、响应正文或原始错误。

密钥仅写入版本 SQLite，浏览器只得到“已配置”状态；留空保留旧值，明确勾选才清除。数据库及备份含自动登录凭据与模型密钥，是私有数据；当前没有透明加密，文件权限不等于加密。

模型只接收必要人格/表达风格/姓名、实际消息或合法目标候选，不发送管理备注、账户密码、其他玩家资产。真人点名/私聊仍可使用模型，陪玩来源或来源未确认的消息使用模板；同一角色收到同一来源的相同消息10分钟内不重复请求。聊天保留30秒宿主冷却及原发言间隔。

不每分钟询问目标。闲时仍只在健康、至少20秒无进度，且同时有适合的可见怪物与公开出口时询问hunt/explore；最多保留2分钟，实际发出原移动/战斗请求后记录采用。另可在多个已接且可打/可达的同优先级任务间选择先后，最多3个候选，输入任务中文名、所在地图/同图跨图和剩余数量；直接复用本次正常规划已有结果，不额外为模型扫描世界。任务建议至多10分钟，每次普通规划重验，日常、交付、补给、减负、筹资、避险和新手就近成长仍优先。行会建会/入会/已获许可攻城与明确点名的30秒切磋也可抉择，详见[行会与攻城](COMPANIONS_GUILDS.md)。每角色决策至少5分钟、任务/行会/闲时同上下文15分钟不重复；单一选项不调用，关闭增强/无效返回/网络失败或额度不足继续规则。不把模型建议当作安全路线、真实战果或资产回执。

自动增强最多2个并发，其中目标建议最多占1个，给实际玩家对话保留名额；每日配额先落库。目标输出上限24 tokens、聊天128，5秒总超时、最多32KiB、严格短文本JSON，拒绝命令前缀和候选外目标。模型失败自动退避5分钟，401/403退避15分钟，同模型的新配置可立即重新核对，避免反复付费失败。过期、死亡、切图、队伍变化使旧建议失效；等待模型的闲时决策仍每100毫秒接收与保护，失败或明确跳过立即回到规则/模板。尚未接入长期聊天记忆、token实际用量/费用统计和外部模型质量评估。

## A/B版本与恢复

持久数据在选中 SQLite 的既有 `snapshots` 中：`companions/settings.json`、`companions/presets.json`、`companions/schedules.json` 和 `companions/profiles/<id>.json`；新写入采用schema2封套（包含模型密钥、昵称池、人格、档案和调度数据）。启动时先校验现有快照，再事务补齐缺失的设置、自定义人格空表及默认日程预设。新版本默认关闭，使用内置人格和昵称，不代建陪玩。未知或错误格式保留原状；已有配置不重置。schema1单模型在内存转换并保留密钥/默认选择，首次编辑前保留已有备份保护。角色账户、装备、任务仍在原引擎快照。

切换版本必须保存、停服、切换完整版本目录并重启。正常停服复制A到B会带上人格、角色、凭据和用量；路径实例标识变化后B总开关自动关闭，须在B明确启用，防止两个副本同时自动上线。恢复原A仍读取A的数据；备份恢复采用完整库/完整目录，不能只回滚单人资产。

执行组件与服务端共用同一构建的 Shared 协议指纹，游戏 TCP 编号和原包布局没有改变。当前私有管道为 `mir2-companion-19`，新增建会材料目标数量/金币预留及报名/集结语义，保留实战降级的怪物编号和鉴定目标编号，保留LLM实际消息来源、闲时候选和采用反馈语义，保留原行会计划/筹资/等待、智能托管和自主组队等语义，须配套更新服务端、`companion/`及管理端；仓库允许编号/数量/方向、拾取候选/可售数量及角色资产没有迁移。未知陪玩schema/字段保留原记录并阻断陪玩写入；工作进程缺失或指纹不符明确报错。地图/NPC/怪物/任务编号从当前已加载版本读取，不硬编码默认世界的中文/英文名称或固定玩法编号；隐藏脚本和特殊入口仍需要后续逐项支持，不能据此保证任意第三方版本全剧情兼容。

注册/进入后的身份绑定与原账户/角色快照在同一SQLite事务保存，任一写入失败一并撤回登记。注册限频在检查前清理过期记录，继续保留原每小时限额。

服务端监管私有子进程；工作进程不打开数据库。控制租约20秒超时主动退出，宿主丢失/管道关闭退出；30秒无心跳默认阻断；“在线调度”开启智能托管后，技术故障先核对旧进程/TCP退出、持久退避重排，有空位时先技术恢复、再核验安全复活点并持久退避处理死亡预算；人工停用/暂停、资产未知/身份/协议/存储保护不解除，详见[智能托管](COMPANIONS_SCHEDULING.md#智能托管)。旧会话事件/模型结果不能污染新会话；监管故障停止陪玩并在兼容页显示阻断，避免连带结束游戏宿主；引擎保存停服前先停止陪玩。地图下载仅在版本runtime下短暂落盘供原解析器读取，完成后删除；内存只保留各会话当前地图，不能当作世界定义。

补给、减负、修理、已齐交付和合法行会活动仍可优先；有可达且能应付的日常时，陪玩优先接取和猎杀，普通购书购装、剧情和练级让路。魔血石按剩余储量换装，普通火把不覆盖。当前任务NPC在合法绑定地图且回城能明显省路时可走原回城卷，留一张应急；低血受怪攻击且不能回城时允许原随机卷逃生。仍按地图权限、串行回执和原资产保护处理，随机落点不保证安全，不作为无目标跑图手段。


### 筹资出图风险

红药与药费不足而前往异图金币源前，除原目标点附近活怪，还以同一承伤预算检查当前地图的首个必经出口。首出口附近已加载活怪的合计预计承伤超过生命上限10%时跳过该来源；有其他安全来源则继续选择，否则保持在线等待并保留药卷、自疗及受击撤退。威胁离开后原查询可恢复该来源，不永久拉黑。只改筹资，不改变正常任务、组队、战斗权限及人工/死亡预算保护；目前没有评估途中每一格或后续地图全程风险，也没有为被堵出口自动寻找另一整条跨图路线。

执行组件在筹资赶路、接近金币怪和走向掉落物时，复用原图内寻路，把当前可见且按战力判断不可应付、或近5秒确实攻击过自己的活怪周围8格暂作障碍。没有可走步时按现有不可达规则排除目标并重查。普通赶路仍用1格，应急单步撤退继续按实际占位选格。8格是保守缓冲，未按各种怪物的警戒范围计算。角色已经身处怪群、怪物刷新或进入视野前的风险仍需单独处理。

应急撤步先选原有可直接减少近身暴露或拉开最近怪距的下一格。转角没有这种首步时，最多向前查看4步，只有每一步都不靠近最近怪物、也不增加近身暴露，且后续确有更安全落点才走第一步。逐次按当前怪物和占位重验，不穿墙、不进入占格或公开出口，无可行退路继续原近身自卫。此局部检查不保证能逃出完整包围，动态追击及多波怪物仍需实际验证。

### 陪玩账户编号

新增、批量和随机新增共用当前版本的`pw数字`账户分配，避开真实账户和未注册陪玩已保留的编号。首次运行新程序时，在陪玩启动前核对旧账户/角色身份及整个账户离线，将旧陪玩账户名与对应凭据在同一SQLite事务改名；编号、密码、资产、档案、用量及人工保护保持，失败回滚。管理员和不匹配账户拒绝迁移，不创建替代账户。角色管理可编辑账户共享金币，仍要求整个账户离线、读取版本一致及保存确认；技能及任务按中文名称显示，任务保留编号。

## 新手效率与实战降级

1–9级红蓝目标最多4瓶，10–19级最多8瓶，20级后沿用人格的原储备；低于目标一半才安排补给。缺钱仍保留原筹资、资产回执和保命检查；预计不受伤的普通小怪允许最多30次普攻，不再仅因超过8次而等待。被动AI1/2未攻击本人时不形成危险缓冲，已经反击及主动强怪的避险保留。移动按服务端实际步跑间隔调度，不再额外固定至少650ms。

对已可见同一目标，15秒无伤害、追逐30秒仍无收益、30秒后仍剩至少一半生命，或实际承伤/围攻过高时，暂排除该怪物90秒，优先尝试较低等级且可应付的来源。路径不可达仅排除刷新点；排除在32项候选上限之前应用，不让旧失败项占满预算。任务不放弃、不伪造进度，恢复后可重试高收益目标。

10级前已有可用武器时，不为普通配饰或鉴定跨图/远走64格以上，已有卷轴可原地鉴定。普通猎杀任务过远且本图64格内有合法经验来源时先就近练级，10级后恢复远途任务；没有本地合法来源不丢弃原任务，补给/修理/交付及日常继续优先。降级后的等待仅针对该次战斗目标，其他目标和普通回收/寻路排除不会被永久锁住，90秒到期可重试。鉴定只看公开最高加成能否提升，不偷看隐藏品质；原NPC必须有实际选项及二次确认，保留半数金币和应急药品。

魔血石采购只使用真实货架与报价，每次1颗、至少保留半数金币；主人和已召唤英雄分别评估。储量大于600不重复采购/来回换石，现用石降至600以下才更换。满血满蓝由原引擎不消耗储量，每2秒实际恢复最多30血/30蓝；非战斗优先石头，近期受击、紧急血蓝、禁药和原回城保护不变。现有盟重九项日常已提供金币、魔血石和卷轴，本轮不增加重复日常或改奖励/倍率。
