# 陪玩系统：管理与运行

当前实现日期：2026-11-13。管理入口为左侧“陪玩管理”（`/companions`）。所有操作绑定管理端显示的版本；首次运行总开关关闭，默认不创建角色、不启用 LLM 或 PK。

## 启用与日常管理

1. 构建服务端会同时生成 `companion/` 执行组件；发布脚本将其打包在 `build/server/companion`，无需另外启动。已运行的旧服务端/管理端需要在合适时间正常重启才能加载本次程序，本次开发没有重启正式实例。
2. 打开“陪玩设置”，启用本版本总开关，设置陪玩在线数与真人预留数量。原服 `MaxUser`、`MaxIP`、封禁、注册频率和登录开关继续生效；调大陪玩在线数不能绕过原服限制。列表显示排队原因及实际限制值；原服总人数和同IP限制在左侧“系统设置”调整，保存后自动重新排队，无需重启。10个陪玩加1个本机真人时，MaxIP至少设为12（另预留1个本机名额）；见[系统设置](SYSTEM_SETTINGS.md)。
3. 新增陪玩：填写原规则允许的昵称、职业、性别，选择人格及作息。保存只登记档案；启动后通过原 TCP 注册随机普通账户、建角、登录，不使用 GM 发物品或传送。
4. “启动”清除该角色错误及人工下线抑制；“暂停”保留连接和药品保护、暂停发展；“继续”恢复发展；“下线”正常退出并抑制当前窗口。到达会话/每日额度时自动下线，休息后再按日程排队。
5. “全部上线”启用当前版本总开关，并为所有已启用陪玩提交启动意愿；暂停角色恢复，人工下线与休息抑制清除。仍遵守日程、配额、人数、MaxIP和注册频率，超额角色排队，不保证全部同时进入游戏。已停用/故障停用角色不自动恢复；确认范围来自当前完整档案，不受列表搜索或分页影响。总开关与启动意愿同一事务保存，失败整体撤回；档案或设置变更后旧确认会拒绝，刷新再操作。
6. “详情”查看账户/角色编号、原因、用量、实时生命/魔力/金币/经验、目标坐标、任务计数、未来七天时段和最近50条运行事件；事件按角色时区以时间/事件/状态/说明表格显示，地图同时显示实时坐标，详情每5秒刷新。真实背包、装备、技能和任务继续在“角色管理”查看，不维护第二份资产模型。
7. “全部下线”关闭当前版本总开关。“解除托管”要求会话已完全离线，只删除陪玩登记，保留原账户、角色和资产。身份绑定后不能在陪玩编辑器改昵称/职业/性别；管理别名随时可编辑。

保存、归档、解除及全部上线/下线使用现有确认弹窗；表单取消不写入，未保存关闭有保护。资料保存采用读取版本检查、完整 SQLite 备份、事务与失败撤回，冲突不会静默覆盖。

## 批量新增

“批量新增陪玩”支持一次1–100个，当前版本总档案上限500个。默认内置100个合法且不重复的网游昵称，如“下班才上线”“菜但爱玩”“装备全靠捡”“欧气借我点”；可在弹窗按行编辑或恢复内置池，支持随机职业、性别、人格，也能指定统一值、标签及日程。默认只创建离线档案，LLM关闭。

先“随机生成预览”，再确认保存。生成时无放回随机选择昵称，过滤原角色/陪玩重名、候选重复和不合法名字；不足明确报错。改数量或参数后须重新预览。预览不写入，取消不保存；确认后全部档案与昵称池在同一事务保存，任一项失败全部撤回。网络重试保留预览编号，不重复创建；昵称池随当前版本SQLite保留。实际TCP注册不是数据库原子事务，由调度遵守原服限制逐个执行。

## 人格与作息

提供随性、懒惰、勤奋、PK狂、热心队友、探索者、稳健、收藏者、节俭、社交、独行、竞技12种预制。人格标识及修订固定，角色保存解析后的十项数值；切换世界定义不会把原人格重新抽签。

勤奋影响短休息；风险影响试怪等级及撤退阈值；对抗影响约战接受；社交/助人影响组队及治疗；探索影响寻路和公开地图入口；节俭影响药品库存及支出预算；收集影响先拾物还是先追怪；坚持影响无进度重新查询的等待时长；健谈影响模板及发言间隔。人格不能提升权限。装备优先目前只影响换装与拾取，并非已实现完整掉落收益预测。

自定义人格由内置复制或创建新修订；旧修订不可原地覆盖。归档只改变新建选择，已有角色保留引用与独立参数；可以恢复归档。

作息支持显式时区、每周多个窗口、跨午夜/全天、出勤概率、上线抖动、单次时长、休息及每日上限。预览只读。固定随机种子保证同一窗口不因刷新/重启重新抽出勤；处理夏令时缺失及重复时刻。没有离线补练。

在线时间以最多10秒的小块提前落入本版本 SQLite，重启不清零；当天和过去24小时都限制，可能保守少用约10秒，不能以重启规避。暂停仍计在线时长。会话结束目前直接按原协议退出，尚未实现提前返回城镇的专用计划。

## 游戏行为

| 行为 | 当前边界 |
| --- | --- |
| 移动与跨图 | 当前地图原 `.map`、SHA-256 校验及有界寻路；服务端按当前版本地图编号规划公开普通步行入口的首段路线，任务和练级均可跨图；探索优先保留独立探索偏好，不执行隐藏跳转 |
| 发育 | 服务端提供适合等级/风险的怪物刷新点及已加载活怪位置；陪玩走到目标区域后按原 TCP 可见对象打怪，基础普攻/已学单体法术、拾取、换装、学书、低血撤退及原回城复活 |
| 任务 | 服务端直接提供可接 NPC、本人进度及真实怪物掉落来源，支持走到视野外 NPC 接取、跨图击杀/收集、返回交付及选择首项奖励；不自动点击任意剧情脚本链接 |
| 补给 | 红药目标12–20份、非战士蓝药目标6–10份，随节俭程度变化；少于目标一半时提前返程，保留路上耗药余量。服务器按当前版本NPC商品、职业/等级、真实单价/税率、金币预算和负重规划公开可达商店；补给优先于猎杀/拾取。原 BUY/BUYSELL 与 REPAIR、串行资产回执继续生效；取下破损装备、修理、重新穿戴。负重达80%或空格≤2时，先出售符合保护规则的普通武器、重复衣服、普通肉及材料/食物余货；只需出售时也可进入原 BUYSELL 页面，不要求同时缺购买物资；减负会话不顺带采购商品 |
| 组队 | 按人格接受/邀请、跟随当前可见队长；学会治疗且满足消耗/冷却时辅助队长 |
| 聊天 | 点名附近聊天、队聊或私聊的有限中文模板，无模型也工作；有发言间隔 |
| PK | 总开关默认关闭。仅自卫使用短时红褐模式；约战需附近玩家明确发出“角色名，切磋”或“角色名 切磋”，限30秒，排除队友/安全区/禁战地图并低血撤退；无目标时恢复和平模式 |
| 不确定结果 | 资产请求串行，匹配原回执；未知资产/移动结果或死亡预算超限停止并显示原因，不盲目重发；长期无进度改为待规划并保持在线 |

服务器每3秒检查一次当前目标：优先交付已完成任务，其次继续未完成击杀/收集，再考虑有目标来源的可接任务，最后寻找有经验收益的适级怪物。收集任务按物品定义编号查询当前已加载 `MonsterInfo.Drops`，包括正概率的分组掉落；不靠昵称猜怪、不要求角色先亲自见过掉落。NPC、刷新点和公开入口均取自当前版本，不维护另一份世界配置。知识查询不代替接取、战斗、拾取、购买或交付，所有执行仍经过原 TCP 与服务端校验；无需启用 LLM。

接近目标、任务/物品进度及经验/金币变化计为有效进展。达到人格允许的无进度时长后，角色会显示“待规划”，暂缓15秒并继续查询，不再因此永久停用；没有合适目标时显示等待原因。原有日程、在线额度、管理员停用和资产结果未知保护仍生效。**已被旧逻辑停用的角色需要在管理页单独点击一次“启动”恢复，程序不会自行覆盖原停用状态。**

本阶段自动接取无未知标记、且有可行目标的击杀/收集、送物及纯拜访任务，按原NPC接取/交付身份区分。普通房屋出口即使不显示大地图图标仍可步行，闭门前发送原Opendoor；洞口、NPC条件入口和攻城入口继续排除，组队地图遵守人数限制。图内寻路最多展开100,000个节点，找到完整绕行路线后缓存；下一格占用、目标或地图改变后重新搜索，NPC直接搜索交互范围内可达格。失败或到达后无进度的目标短暂排除后重选；超出搜索预算的复杂地图仍可能暂不可达。特殊洞口、攻城入口、脚本传送、付费/条件跳转与任意复杂剧情仍需逐项支持。

站在目标出口格但尚未切图时，发送原 Turn 包重试原引擎 CheckMovement，不要求先挤出相邻格再踩入；补给途中遇袭也保留该行为。仍以服务器切图回执为准，遵守原移动/洞口权限，15秒无进度后报告目标排除，不能把已站在出口当成跨图完成。补药统计只计自动保护支持的形状0/1、正恢复值及正数量药品，购买优先普通药品并按单份报价核算，不将特殊药品、整堆价格或无效库存当成可用补给。

原栗树（Tree/AI3）仅接受普攻，每次有效命中扣1点生命，火球等法术仍耗蓝但不造成伤害。陪玩和微端挂机共用ClientAutomation判断，按原ObjectMonster包中的AI改用普攻；不按中文名称、素材或版本内怪物编号猜测，也不跳过该目标。不改变原怪物规则、原TCP或私有管道契约；其他特殊免疫/抗性尚未形成完整策略。

陪玩在7格内持有可负担的远程攻击法术时优先已就绪技能；全部冷却时保持已有射程，继续按短行动周期检查保命，不主动走近目标填补冷却。已经贴身仍能普攻，缺蓝或没有可用法术时仍走近普攻，Tree保持原普攻规则；规则约战也共用此选择，不改变原PK开关和权限。尚无完整绕怪风筝、法术耗蓝/免疫收益或多怪威胁评估；不得据此称长期药费问题已解决。

回补途中遭受实际怪物攻击时，能规划通向补给NPC/出口的下一步就先尝试撤离，不先打完每只追击怪；原位置回执、占格和非目标出口限制不变。路线暂不可用时，低血或对手不适合当前战力仍尝试远离附近怪物，无路且被近身时自卫。死亡事件记录会话次数、地图坐标、药量及当时目标，原死亡预算仍会停用角色；这不代表已具备复杂围攻、远程风筝或任意危险地图的生存保证。

已学治愈术的角色在生命不高于80%、MP足够且没有待确认药品/资产操作时可通过原Magic包自疗；原低血喝药仍优先。自疗至少间隔5秒，并遵守当前版本技能更长的冷却和装备耗蓝惩罚，施法后留出1.8秒全局间隔；交易/仓库中不施放，暂停发展仍保命。原服确认的自疗在最近事件中显示“自疗回执”，不预扣MP或直接加血。原引擎持续回血、技能等级及权限仍权威执行；当前客户端属性估算未覆盖全部套装/Buff，拒绝或无回血不能当作成功，仍不保证围攻生存。

生命不高于35%、当前地图允许回城且不在安全区时，可用背包中正常获得的原回城卷轴（Scroll/Shape1）保护。服务器提供独立NoTownTeleport标志；NoEscape限制地牢逃脱，NoDrug限制药品，不能代替禁回城。未知地图/缺失标志默认不回城，禁药图仍可按原规则使用合法回城卷。复用ClientAutomation单个待确认请求，原UseItem成功才扣卷，拒绝/超时停止且不重发；地图暂时禁用保护不重置同一次低血触发，实际恢复生命后才重新布防。回城事件只表示原服确认使用，落点及后续补给还需实际核对，无可用卷时仍走原步行路线。

当前地图允许回城、没有本人可用卷且预算/空格/负重允许时，可按当前版本公开商人的实际货架补购1张。服务器优先选择能补当前缺药的商人，再考虑补卷；执行组件购买同样先药品、再卷轴、再装备。双方沿用单价、原NPC税率和人格预算，不为买卷另放宽金币限制；满1张不继续囤购，现有2张也不出售或改动。只识别原Scroll/Shape1、本人职业/性别/等级和允许使用的租赁标志，其他需求类型保守跳过；原服务器仍最终校验商品、会话及所有使用条件。没有用缺卷为由新增随机拜访，不自动创建商店商品或GM补卷。

前往其他地图的猎杀目标时，行程优先于沿路拾取、主动追怪及临时查找无关商人，实际遇袭仍会自卫；已经发出的交互仍正常收尾，服务器明确规划的补给/减负照常执行。到达目标地图再恢复战斗和拾取，避免反复捡满、回城而一直未到达任务地图。

减负处理普通多余武器、同一定义的普通重复衣服（Armour）、普通肉（Meat），以及普通材料/食物（CraftingMaterial/Food）的多余数量；材料/食物按物品编号跨堆叠至少保留5份，达到减负目标后不保证每类都恰为5份。衣服只在已有装备时处理背包重复件，每种定义保留当前耐久最好的一件；不同定义的唯一衣服不比较优劣、不出售，未知堆叠或最大耐久偏离定义的衣服也保留。服务器给出唯一编号及最多可售数量，执行组件再次计算，取双方允许数量的较小值并走原SellItem回执，不预扣库存。普通肉满包或达到负重线也主动规划支持肉类的可达商人，不必等碰到附近NPC；正常肉品质超过定义耐久仍有效，未知堆叠/特殊属性保留。明确减负会话只处理当前允许清单，没有允许项时停止出售，不能回退临时卖肉绕开全版本任务/配方保护。保留已装备物、一把当前可用备武器、升级/未来等级武器、全版本任务收集/携带物及已加载配方的材料/工具，并沿用绑定/租赁/附加属性/精炼/觉醒/镶嵌/稀有/工具等保护；原普通肉出售规则继续保留。不会自动丢弃、删除或存仓，其余非武器装备、矿石、药卷及受保护库存积压仍有限制。管理详情显示真实负重上限及空格。

普通地面拾取预留20%负重及2个空格，当前必需任务物可按实际剩余容量处理；金币仍可在满包/超重时按原金币上限拾取。服务器按当前可见物品、归属及原CanGainItem/CanGainGold提供有界候选，原PickUp没有目标编号，因此只评估同格原顺序中真正会先拾取的一件，不跳过重物选择其下金币。执行组件入包后清空旧候选，等待下一次知识快照。非任务尸体采集同样在减负阈值以上暂缓，必要任务采集仍遵守原归属与格位。以上是自动决策保护，没有改变原玩家拾取规则，也不承诺并发抢拾/延迟下的硬性负重上限。

尚不自动操作玩家交易、行会资产、邮件领取、拍卖、锻造、仓库密码或任意复杂剧情；未知版本内容在“兼容与能力”中显示限制。这些内容仍由原引擎与人工管理处理。

## 可选 LLM

模式为关闭、仅社交、社交与候选目标建议。陪玩设置可以管理最多20个模型，每个模型独立设置显示名称、完整 Chat Completions HTTP URL、模型标识、密钥和启用状态，并选择默认模型。陪玩开启增强后可选择具体模型或使用本版本默认模型；稳定编号防止重命名时串用密钥。已被启用增强的角色显式引用时，移除模型会被拒绝；停用/不可用时回落规则。可用本地兼容服务，没有新增SDK依赖。

“可选 LLM”旁、模型编辑弹窗和角色模型选择旁都有网络检查图标。测试发送一次真实短请求，验证地址、鉴权、模型和短文本JSON，显示成功/错误和耗时；使用当前输入但不保存模型草稿。测试计入本版本每日模型额度，最多2个并发，同模型5秒间隔；不向浏览器回传密钥、响应正文或原始错误。

密钥仅写入版本 SQLite，浏览器只得到“已配置”状态；留空保留旧值，明确勾选才清除。数据库及备份含自动登录凭据与模型密钥，是私有数据；当前没有透明加密，文件权限不等于加密。

模型只接收必要人格/表达风格/姓名、实际消息或合法目标候选，不发送管理备注、账户密码、其他玩家资产。每角色30秒请求冷却、自动增强最多2个并发（手动测试另有并发保护）、每日配额先落库；响应总超时5秒、最多32KiB、严格短文本 JSON，拒绝游戏命令前缀。过期、死亡、切图、队伍变化使旧建议失效；失败回到规则/模板，不阻塞收包、喝药或下线。尚未接入长期聊天记忆和外部模型质量评估。

## A/B版本与恢复

持久数据在选中 SQLite 的既有 `snapshots` 中：`companions/settings.json`、`companions/presets.json` 和 `companions/profiles/<id>.json`；新写入采用schema2的明确封套（包含多模型选择和昵称池）；schema1单模型在内存转换并保留密钥/默认选择，首次写入前完整备份；只读不升级落盘。角色账户、装备、任务仍在原引擎快照。没有全局可写人格库、额外数据库或跨版本共享状态。

切换版本必须保存、停服、切换完整版本目录并重启。正常停服复制A到B会带上人格、角色、凭据和用量；路径实例标识变化后B总开关自动关闭，须在B明确启用，防止两个副本同时自动上线。恢复原A仍读取A的数据；备份恢复采用完整库/完整目录，不能只回滚单人资产。

执行组件与服务端共用同一构建的 Shared 协议指纹，游戏 TCP 编号和原包布局没有改变。独立禁回城标志使私有管道升级为 `mir2-companion-6`，须配套更新服务端、`companion/`及使用目标DTO的管理端，不能混用旧组件；保留已有拾取候选/可售数量，没有新增存档 schema 或迁移角色资产。未知陪玩schema/字段保留原记录并阻断陪玩写入；工作进程缺失或指纹不符明确报错。地图/NPC/怪物/任务编号从当前已加载版本读取，不硬编码默认世界的中文/英文名称或固定玩法编号；隐藏脚本和特殊入口仍需要后续逐项支持，不能据此保证任意第三方版本全剧情兼容。

注册/进入后的身份绑定与原账户/角色快照在同一SQLite事务保存，任一写入失败一并撤回登记。注册限频在检查前清理过期记录，继续保留原每小时限额。

服务端监管私有子进程；工作进程不打开数据库。控制租约20秒超时主动退出，宿主丢失/管道关闭退出；30秒无心跳阻断该角色并等待人工处理，旧会话事件/模型结果不能污染新会话；监管故障停止陪玩并在兼容页显示阻断，避免连带结束游戏宿主；引擎保存停服前先停止陪玩。地图下载仅在版本runtime下短暂落盘供原解析器读取，完成后删除；内存只保留各会话当前地图，不能当作世界定义。
