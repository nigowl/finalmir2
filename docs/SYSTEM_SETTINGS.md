# 系统设置

管理入口：左侧“系统设置”（`/settings`）。配置归属当前版本的 `world/Configs/Setup.ini`，沿用原引擎参数，不增加第二套配置数据库。陪玩档案、人格、日程、模型和密钥仍保存在本版本 SQLite；“陪玩设置”是陪玩自身的调度上限。

## 陪玩人数与 MaxIP

“最多同时在线陪玩”不会覆盖原服限制。陪玩共用服务端本机 IP，调度还会额外保留 1 个本机连接，以免真人本机连接触发原服整 IP 保护。

例如要同时运行 10 个陪玩，还要允许 1 个本机真人连接：

- 陪玩设置：最多同时在线陪玩为 10。
- 系统设置：同 IP 最大连接数至少为 12（10 个陪玩 + 1 个真人 + 1 个预留）。
- 系统设置：最大在线连接数要覆盖这些连接和陪玩设置中的真人预留数量；其他真人连接也占总名额。

陪玩页面显示陪玩上限、总连接上限、真人预留、同 IP 连接上限和理论陪玩上限；排队原因显示实际连接数。提高人数或 MaxIP 后保存即生效，调度自动重新判断，无需重启或逐个重新启动。

“同 IP 每小时注册次数”和“同 IP 每小时建角次数”独立于同时连接数，默认分别为3和5，0表示不限；两项保存立即生效，原TCP与陪玩调度共用同一规则。按过去一小时请求次数计数，成功和失败尝试都计入；修改不清空已有计数。短时连接频率、既有封禁、注册/建角权限和账户最多5角色规则仍保留。

## 参数与生效范围

| 分组 | 参数 | 生效方式 |
| --- | --- | --- |
| 连接与权限 | 最大在线连接数、同 IP 最大连接数 | 保存后应用于新连接和陪玩调度；不会强制踢下已有玩家 |
| 连接与权限 | 同 IP 每小时注册次数、同 IP 每小时建角次数（0–65535） | 0为不限；原TCP和陪玩调度在下一次请求/排队时生效，写入Network的MaxAccountsPerIPHour、MaxCharactersPerIPHour |
| 连接与权限 | 注册、登录、改密、创建/删除角色、仓库密码 | 后续原协议请求按新权限校验；关闭登录不强制下线已有玩家 |
| 连接与权限 | 启用战士/法师/道士/刺客/弓箭手职业 | 五项独立控制新角色创建；不影响已有角色登录，还须开启“允许创建角色” |
| 成长与掉落 | 经验倍率（0.01–1000）、掉落倍率（0.01–100） | 保存后用于后续奖励；掉落倍率也影响原任务金币奖励，不是额外独立金币倍率 |
| 成长与掉落 | 公共商店价格倍率（1–10，默认1.5） | 未单独设置倍率的商城商品按基础买价乘系统倍率并向上取整；商品倍率留空恢复跟随。保存前检查金币范围，保存后立即失效旧报价 |
| 成长与掉落 | 普通/死亡掉落保留时间（分钟） | 后续新掉落使用新值，已有地面物品倒计时不重算 |
| 成长与掉落 | PK 值衰减间隔（秒）、怪物等级差经验修正 | 后续计算使用新值，已安排的衰减不提前 |
| 成长与掉落 | 金币掉落开关、每堆金币上限、落点搜索格数、同格堆数 | 后续新掉落生效；满落点终止分堆，不生成零金币堆 |
| 自动学习 | 升级自动学习开关、五职业技能多选 | 保存后从下次升级检查；按当前版本真实学习条件补学，不消耗技能书或金币，不改变已学技能 |
| 战斗平衡 | 玩家物理/法术、PvP额外、野怪、战宠伤害倍率 | 后续原伤害结算；按原防御类型分物理/法术，保留原权限、防御和抗性 |
| 战斗平衡 | 玩家基础攻速修正 | 保存后刷新在线玩家/英雄并通过原基础属性包同步；每点约60ms，原550ms下限保留 |
| 战斗平衡 | 走跑间隔（300–1000毫秒，默认500）、角色动作速度（80–150%，默认110%） | 保存后正常重启引擎。客户端通过资源清单取值，陪玩从服务端进程接收同一配置。用于走跑、普攻、全局施法间隔及人物动作 |
| 战斗平衡 | 技能冷却时间倍率 | 保存确认后正常重启引擎，重新登录时同步原技能元数据；不改变原全局动作间隔 |
| 战斗平衡 | 暴击率系数、暴击伤害除数、幸运基数、PvP抗魔 | 后续原概率/伤害结算 |
| 状态效果 | 红绿毒/流血时间、绿毒/流血伤害、控制时间、技能Buff时间倍率 | 后续新施加状态；不重算已有状态、不放大固定延时爆炸、物品Buff和永久状态；盾受击只扣剩余时间 |
| 状态效果 | 魔抗/毒抗/冰冻/毒素判定基数、生命/魔力恢复除数、PvP抗毒/冰冻 | 原抗性、恢复和权限判断 |
| 怪物平衡 | HP/物防/魔防、攻击/移动速度倍率 | 新刷出或原属性刷新生效；不强制重置现存生命，保留原速度下限；包含战宠基础属性 |
| 怪物平衡 | 首领驯服上限、战宠保存 | 原驯服和退出恢复规则，不能突破怪物定义权限 |
| 存档与保护 | 自动存档间隔（分钟） | 下一次已安排的自动存档完成后使用新间隔；需要时可在运行监控立即保存 |
| 存档与保护 | 安全区边界、安全区恢复 | 原引擎在建图时生成效果，保存确认会明确提示正常保存并重启引擎，玩家需要重新连接 |
| 存档与保护 | 怪物召回开关、距离（格）、冷却（毫秒） | 后续怪物处理使用新值；仍需怪物定义允许召回 |

共64项参数（包括自动学习开关及五份职业技能列表），角色创建及NPC职业限制支持五职业；职业智能辅助和陪玩创建仍仅支持战士、法师、道士，陪玩也遵守对应创建开关。已有职业装备、商店和掉落定义继续使用，不从导入目录覆盖当前世界。基础倍率默认1；技能/控制/毒/Buff时间倍率0.1–10，怪物速度倍率0.1–5，攻速修正-20–30，判定基数及恢复除数1–255（禁止零除数）。怪物稀有度仍在MonsterRarity.ini，本页不另造一份配置。

人数范围 1–65535；伤害/经验/爆率等倍率 0.01–100；存档间隔 1–60 分钟；物品保留 1–1440 分钟；PK 间隔 1–3600 秒；召回距离 1–100 格、冷却 100–600000 毫秒。服务器独立验证范围，不依赖网页输入控件。网络端口、监听地址、管理密钥和原协议保护不在此页开放修改。

## 升级自动学习

“自动学习”页默认关闭，五个职业均默认不勾选技能。编辑时按战士、法师、道士、刺客、弓箭手分别多选；技能清单来自当前版本实际存在的技能及技能书，显示名称和最低学习等级。同一技能去重显示，不能提交其他职业、未知或重复技能。

开启并保存后，角色下次升级时检查所有已勾选但尚未学会的本职业技能；跨多级时也会补齐符合条件的技能。除技能等级门槛外，仍检查技能书的职业、性别、等级或属性要求；同技能有多份书时，任意一份符合即可。此功能直接授予技能，无需背包持有书籍，也不会扣书或金币，聊天框显示“升级自动学习：技能名称”。

已学技能保持等级、熟练度和快捷键；关闭开关或取消勾选不会删除技能。保存设置和登录不会立即补学，等待下一次升级。设置写入当前版本 `Setup.ini` 的 `[AutoLearnSkills]` 节，技能选择以既有 `Spell` 编号保存；角色仍使用既有技能存档和 `NewMagic` 包，不改变协议及快照格式。

## 保存与恢复

页面以表格读取，编辑使用统一弹窗和“取消 / 保存”。保存前再次确认；取消及预览不写入，未保存修改关闭有保护。

七个分组均在当前值旁显示默认值，单位及开关格式一致。默认值取程序初始参数，并由全字段回归核对，不随当前配置变化。编辑底栏“重置”确认后恢复全部默认值，包括关闭自动学习、清空五职业选择，只修改草稿；点击保存才写入当前版本，取消编辑不落盘。重置若改变安全区效果或技能冷却，保存仍须确认正常重启。

`/management/settings` 必须携带匹配的 `X-Mir2-Version`。运行参数由游戏线程读取/应用；写入沿用管理写入串行链路。保存同时核对配置文件版本与已读运行值，冲突拒绝覆盖。仅更新白名单键，保留未知节、其他键、注释及端口；重复的受管节/键须先在游戏开发中修正。

写入沿用文本备份及原子替换：完整旧文件保存在本版本 `runtime/backups/text-*/Configs/Setup.ini`。备份或落盘失败不会先改变运行参数。确认后已开始的保存/必要重启不因浏览器断线而中断。恢复配置应先正常保存停服，再从备份恢复对应文件并重新启动，勿把其他版本的玩家数据库混入。

已有运行中的旧服务端和管理端需要正常重启一次以加载此次程序；加载后，常用热更新参数无需每次重启。手工在游戏开发或磁盘修改配置仍沿用原来的重启加载方式。

## 验证入口

- `dotnet build Mir2.sln -c Release`
- `MIR2_DATA_ROOT="$PWD/data/versions/default" dotnet run --project tests/Compatibility/Compatibility.csproj -c Release`
- `./tests/Management/administration.sh`：人数/倍率热更新、权限/冲突/范围校验、安全区/冷却重启、平衡值及整机重启保留。
- `./tests/Management/ui.sh`：统一按钮/表格/弹窗及原管理交互。
- `dotnet run --project tests/Compatibility/Compatibility.csproj -- --settings-checks`：默认值一致性、五职业独立开关、范围/版本/备份失败保护和配置保存。
- `dotnet run --project tests/Compatibility/Compatibility.csproj -c Release -- --auto-learn-checks`：五职业学习条件、重复保护、配置校验与保存/重载。
- `bash tests/Compatibility/auto-learn.sh`：只运行自动学习相关构建、小检查、管理浏览器五职业多选/保存/取消/重置及原TCP升级/完整重启，需已有Playwright。可通过 `NODE_PATH` 指定依赖、`MIR2_BROWSER_EXECUTABLE` 指定浏览器；`MIR2_TEST_KEEP=1` 保留截图和日志。
- `MIR2_SETTINGS_UI=1 ./tests/Management/ui.sh`：六页默认值、重置确认/取消/草稿/保存和未保存关闭保护；也可在已有隔离版本启动后单独执行`settings.cjs`，避免重复完整夹具构建。
- `MIR2_COMPANION_UI=1 python3 tests/Companions/smoke.py`：MaxIP 排队后提高上限自动上线、设置表单确认/取消、陪玩坐标与格式化事件及原陪玩流程。

以上均在临时版本和独立端口运行。人数可配置范围不代表经过相同规模的容量验证。

运行监控的保存、启动、停止与重启使用同一个生命周期锁。操作开始后不因浏览器取消而中断；停止/重启先在游戏线程完成可报告失败的完整保存，再清理陪玩及TCP。保存失败保持引擎运行，不误报成功；退出异常不继续启动。跨轮次的旧排队管理操作拒绝执行。运行监控在线列表默认每页10条，自动刷新保留当前页，尾页收缩时回到有效页。
