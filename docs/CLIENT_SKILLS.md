# 微端技能核对与验证

## 依据与边界

以原客户端 `37aaadb4` 的 `Client/MirObjects/PlayerObject.cs`、`SpellObject.cs`、`Effect.cs`、`Client/MirScenes/GameScene.cs` 和当前 C# 服务端为依据。公共协议布局、原伤害公式及正式版本玩法定义不因本次修复改变。

当前 `Spell` 有 110 个小于200的玩家技能枚举。`FastMove`（瞬步）仅是原引擎预留：默认定义的创建代码已注释，也没有主动执行分支；界面明确禁止施放。其余技能按原实现区分有独立素材、普通动作、被动、状态回执或召唤实体，不给本来没有独立光效的技能编造特效。

## 技能列表与游戏菜单

技能列表移除自动释放复选框；被动技能不显示快捷键设置，原开关技能仍可点击图标/快捷键切换，开启状态着色回显并沿用服务端保存。主动技能保留图标点击、F1–F12和冷却显示，自动释放统一在职业/挂机页设置。装备对比列之间和差异区上方使用独立分隔线。

快捷栏上方移除操作说明，菜单按战斗/界面/社交/角色分组并显示快捷键：Ctrl+Z开始/停止挂机、Ctrl+H轮换攻击模式、Ctrl+O设置、Ctrl+E菜单、Ctrl+L切换角色、Ctrl+Q退出；切换/退出有确认。I/C/K/Q/M/G/P/T/H沿用背包/角色/技能/任务/地图/拾取/组队/交易/行会，F1–F12全部保留技能。聊天和文本输入焦点内忽略游戏快捷键。

菜单不保留常驻复活项。死亡后弹窗选择回城复活或暂不复活，取消后R重开；按原TownRevive回执恢复，复活、断线或换角色清理弹窗。

## 按职业显示的辅助设置

游戏设置按当前角色显示战士、法师、道士、刺客、弓箭手五职业。职业页的“智能组合”默认开启，手动选中野怪攻击与挂机共用；勾选时收起逐项技能辅助，取消后显示原手动辅助开关（各项默认关闭）。不选怪、不开挂机时，不因智能组合自行攻击或施法；药品/随机/回城保护及自动拣取仍默认关闭。挂机页移除单体/群攻选择，技能统一由职业控制。角色创建仍由服务端五职业独立开关控制，不改已有角色身份或已学技能。

| 职业 | 智能组合与逐项辅助覆盖 |
| --- | --- |
| 战士 | 按原服准备回执使用攻杀；优先消费已准备烈火/双龙，双龙自动准备前预留准备与出刀两次耗蓝，半月/圆月按实际扇区多怪选择，剑刃风暴按范围选择。手动开启刺杀可原地攻击直线第二格，智能模式兼顾近战爆发准备。维护护体神盾、狂暴、狂怒和反击；金刚不坏会降低物攻，智能模式仅在低血或贴身围攻时使用，手动开关仍可明确启用。 |
| 法师 | 先维护魔法盾/魔法强化、可用时补镜像；单怪按已学的灭天火、雷电、大火球、火球选择，低血可用吸血。群怪按真实范围选择火墙、火龙气焰、冰咆哮、流星火雨、暴风雪、雷电风暴、爆裂火焰、疾光电影、地狱火及冰柱；周身/直线技能不能仅因远处怪物聚集就空放，同一目标区域已有火墙不重铺。 |
| 道士 | 自疗/净化优先，之后补召唤、补目标红绿毒，再维护幽灵盾、神圣战甲术、终极强化、能量盾及本人宠物强化，最后用火符或多怪毒云攻击。已有毒/增益/宠物时不反复消耗；智能模式自动选择已学且耗材/冷却满足的召唤术，取消智能后可指定召唤技能。 |

| 刺客 | 战斗时维护疾风步、轻身术，单体双重斩，群体按前方五格扇区选择弯月斩或直线三格神圣剑术；缺蓝回退普攻。隐身、分身、陷阱及突进仍保留手动。 |
| 弓箭手 | 战斗时维护元素屏障、凝神；无元素且已学冥想时，确认原元素回执后再开盾，不把聚元素误判成施盾失败。单体双重射击/直线射击，多怪燃烧箭，半血优先吸血箭；缺蓝继续原弓箭普攻，有关元素射击、召唤图腾/控制与位移仍手动。 |

技能选择保留原MP惩罚、耗材、冷却及特殊怪物AI限制；Tree只用原普攻，缺蓝/缺材料回退普攻，远程主攻仅在冷却时不因短暂等待而贴脸。推怪、冲撞/突进、传送、诱惑、隐身、困怪、诅咒/瘟疫、复活及队友群体治疗等依赖场景/对象意图的技能保留手动；没有把每个技能都设成无条件轮放，也不宣称对全部Boss、PvP和配装都达到数学最优。

攻杀沿用原服每次普通攻击的准备概率（0–3级分别为1/12、2/12、3/12、4/12），实际使用准备后的攻杀才增长该技能熟练度；达到当前熟练等级/角色等级限制时不继续增长。客户端提示说明概率及间歇特效，不把攻杀改成每刀必出。刺杀本身不耗蓝；第二格实际命中补上原来遗漏的LevelMagic与MagicLeveled回执，前后两格同时命中不重复练功。

镜像沿用原同名ObjectPlayer回执识别，不误当成ObjectMonster而超时暂停；道士宠物仍按原MasterObjectId识别。原协议只有视野内信息，远处宠物/镜像仍由服务端处理召回，不能宣称掌握全图宠物状态。

毒粉/护符按原装备扫描顺序、形状和单叠数量准备；一次只发一个原EquipItem/RemoveItem，成功回执后再读装备继续。毒云同时核对5份护符和5份绿毒，使用原合法护符/右腕位；无空格不能卸下优先毒粉。客户端不预扣物品、MP或伪造宠物。施法后等待真实Buff、宠物MasterObjectId、中毒标记或实际回血；拒绝或6秒未生效暂停职业动作，换装3秒未确认保留未决锁且不重发，超时后仍可手动移动。检查后在职业页更改并自动保存可恢复，未决换装须先收到回执或重连。

交易、仓库和NPC交互期间暂缓，普通走图不强行插入维护动作；死亡、切图清除待施法目标，断线/换角清除本次协调状态。所有权限、耗材、召唤限制、伤害及状态持续时间仍由原服务端决定。启动失败会将原引擎最近错误带入宿主异常，避免只有“启动失败”而看不到真实原因。

## 可复现检查

```sh
dotnet build src/Client/Client.Godot.csproj -c Release
# 局部迭代先跑以下核心检查与实际改动场景，不每轮运行完整套件
MIR2_DATA_ROOT="$PWD/data/versions/default" dotnet run --project tests/Compatibility/Compatibility.csproj -c Release -- --client-checks
bash tests/Compatibility/class-combos.sh
MIR2_DATA_ROOT="$PWD/data/versions/default" dotnet run --project tests/Compatibility/Compatibility.csproj -c Release
MIR2_DATA_ROOT="$PWD/data/versions/default" dotnet run --project tests/Compatibility/Compatibility.csproj -c Release -- --skill-assets
MIR2_TEST_KEEP=1 ./tests/Compatibility/skill-effects.sh
MIR2_TEST_KEEP=1 MIR2_NATIVE_VISIBLE=1 MIR2_TEST_SCREENSHOTS=1 ./tests/Compatibility/smoke.sh
python3 tests/Companions/ranged.py
```

- `--skill-assets`只读所选版本素材，逐帧检查八方向/等级近战、十六方向弹道、起手/命中/持续及状态素材；当前555段、3705个独立帧。它验证图号有效和非全空，不能代替实窗检查。
- `SkillDamageChecks`在内存隔离地图执行原攻击和延迟结算：普通攻击、烈火准备/实际HP/耗蓝/重复与冷却拒绝/未准备降级，其他六种近战，以及火球、大火球、雷电、灵魂火符、寒冰掌、灭天火、强力矢、二连射的实际HP/MP与冷却拒绝。固定100攻击、10附加、2倍率时，普通实际扣100HP，烈火扣220HP；双段技能按原两次结算，未改原公式。
- 同一原引擎隔离检查另核对红毒实际降防、绿毒实际扣HP、各一份耗材/11MP，及火墙遵守安全区、离开后连续扣HP；职业规则检查逐项默认关闭、五职业白名单、冷却/MP边界、已有宠物、交易/仓库、双耗材/扫描顺序/满包、智能半月真实扇区和Tree回退。
- `skill-effects.sh`创建临时版本、独立端口/缓存和高生命靶怪。真实Godot/Metal和原TCP验证烈火耗蓝/命中及六帧、火球/雷电/灵魂火符/冰咆哮、治愈实际回血、走出安全区后的火墙多次伤害、魔法盾；远端七种近战逐帧绘制，失败施法与切图清理。法师/道士使用独立账号，保留原召唤兽定义，核对当前职业动态页、真实Buff/召唤、毒符换装及红绿毒、禁宠图暂停；战士页由完整smoke检查。结束正常停止自己创建的服务端，不操作正式数据或实例。
- `smoke.sh`保留整套游玩、界面/快捷栏、交易/行会资产、GM及正常保存/SQLite重启检查；`ranged.py`确认陪玩5秒冷却原地三次扣蓝击杀及0MP普攻回退。

没有把素材覆盖或公式抽样等同于110项全部伤害组合验证。全部职业等级/装备/抗性/PvP/召唤/特殊Boss交互和长期多人特效压力仍需独立场景；未发布或重启正式实例。

## 基础剑气与战斗飘字

按本轮明确要求，战士本人学会且未禁用基础剑术后，原`Spell.None`普通攻击增加淡剑气：复用原低阶剑光八方向、六帧和600ms时长，透明度0.38以区别攻杀；预热整段素材后播放。它属于客户端表现扩展，不改变原基础剑术的命中规则、伤害、熟练度或协议技能编号。原协议未同步他人被动技能清单，暂不向其他战士推断基础剑气；原主动近战特效保留。

战斗数字消费原`DamageIndicator`回执，按实际伤害绝对值递增字号并限制基础字号15–36；普通命中、原服暴击、治疗加号和未命中区分颜色，配合描边、轻弹出、上浮及渐隐。不会根据伤害大小猜测暴击，也不预改HP/MP。可见Buff的新增、恢复和消失使用现有中央枚举中文名称，护盾升降提示去重；不可见Buff和未知恢复包不泄露名称。

飘字在地图特效上方的独立普通混合层绘制，跟随同帧镜头和人物插值；最多128条，Buff状态最多1024键，移除对象、切图、换角及断线清理。`--client-checks`覆盖基础剑气限制、伤害边界和Buff中文；已有隔离原生游玩fixture可用`--verify-combat`只验证设置底栏、CRT像素、原服已学基础剑术普通攻击六帧及真实伤害、飘字生命周期。Buff边界用本地注入原包验证表现，不等同于本轮逐个技能真实施法验证。

普通攻击完成后沿用原客户端约2.5秒战斗准备姿势，不在两刀之间立即切回日常站立；近战起手前连同原准备姿势素材一起预备。只改变展示，原攻击间隔、完整六帧、双连斩两段及服务端动作/伤害规则不变；持弓旧角色保留原站立分支。

## 拣取、探索与设置重置

挂机页“自动拣取”默认关闭，开启后显示黑白名单及物品名称输入。排除模式拣取名单以外的物品，空排除名单为全部；指定模式只拣取名单内物品，空指定名单不拣取。完整名称匹配，忽略原堆叠数量后缀，金币统一填写“金币”；最多64项、每项40字，设置文件读取上限64KB。战斗优先，空闲时选附近8格内允许且可达的物品，仍使用原PickUp，由原服验证归属、负重、空间和金币上限；同格混有排除项时整格跳过，避免原包跳过首件后误拣。未决请求不重复发，3秒无移除回执暂停，迟到回执释放；切图/死亡/换角/断线清理，客户端不预增物品或金币。

无怪跑图选择32–96格的较远候选，按近期实际到访的16格区域评分；最多记128个区域和32个短时不可达点。目的地保留到到达，战斗/拣取后续行，切图清理旧路线；仍使用原地图格位和AStar，不保证所有复杂迷宫都能遍历。

设置底部“重置”先确认，再通过原子写入恢复所有默认值、重建控件、应用音量/显示并停止本次挂机。取消不重置，写盘失败保留旧文件及已应用设置；不清除未确认的药卷/换装/拾取锁，也不改服务器技能、快捷键或角色数据。

`--verify-ui`检查重置取消/失败/确认及名单保存；隔离smoke fixture的`--verify-automation`检查真实丢弃/拣取的名单切换、一次回执与数量/金币守恒，以及真实远距离移动和目标保持。`class-combos.sh`只构建相关项目，运行小型规则检查及真实Godot五职业组合，额外核对攻杀/刺杀熟练度、手动智能单体和道士先毒后增益；不执行完整管理/交易/部署套件。

## 2026-11-17 五职业与陪玩共用

陪玩复用 `ClassSkillRules.Next/AttackMagic/WaitForRanged/Melee`，包括原技能准备、护盾/召唤/毒和安全耗材换装；拒绝或6秒未确认生效暂停本会话自动施法，不重发，仍保留药品保护、撤退与普通战斗。原TCP/包字段不变，实际伤害、蓝量及耗材仍由原服执行。

弓箭手凝神的内部状态曾在.NET 8保存时触发原BinaryFormatter禁用异常。现只读写当前实际使用的bool/long，保持原NRBF字节完全相同并拒绝未知类型/破损数据，不启用任意对象反序列化或迁移存档。`BuffDataChecks`包含旧格式样本和边界。

`tests/Companions/class-skills.py`在隔离原TCP版本验证五职业技能实际熟练度、击杀经验、耗材与装备编号及完整重启；`class-combos.sh`扩展五职业，`--class-extension-only`仅用于重跑刺客/弓箭手实窗。真实Godot中已有Buff不重复补、手动辅助页与实际伤害均检查；不宣称每个职业的所有技能都自动化或长期围攻无死亡。
