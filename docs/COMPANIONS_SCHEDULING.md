# 陪玩随机加入与智能调度

管理入口：“陪玩管理 → 陪玩设置”，分为“在线调度 / 随机新增 / 可选 LLM”。本系统不依赖LLM，所有设置、计时、档案、人格和用量均保存在所选版本的SQLite中。

## 随机新增

默认关闭。启用后填写最短、最长间隔，范围为 **1分钟–1个月**；一个月固定按30天即43200分钟计算，界面支持分钟、小时、天、月。默认30–120分钟，两个值相同表示固定间隔。内部统一分钟配置，在包含边界的秒级区间内均匀抽取触发时间，调度循环约每秒检查；这不等于保证精确到秒执行。

1. 首次启用时只安排一次未来触发，不立即创建，不提前生成一串事件。
2. 到期后只尝试新增1名陪玩。昵称从当前版本昵称池无放回选取；过滤现有角色/档案重名、重复及非法昵称，职业只选当前版本已开放的战士、法师、道士、刺客、弓箭手，性别和未归档人格随机。单个创建、固定/随机批量及随机新增复用同一职业开关；已有角色不因关闭创建开关而禁止登录或改职。
3. 新档案与唯一下一次触发时间在同一SQLite事务提交，失败整体撤回；新档案默认启用自动日程，LLM和PK关闭。账户和角色稍后通过原TCP正常注册、创建、登录，仍受原服注册及建角频率限制。
4. 下一次触发从本次实际处理时间开始，再随机抽取。宿主重启保留已安排时间；停机错过多次间隔也只处理当前一次，不按逾期次数补建。
5. 总量默认最多100个档案，可设置1–500，**包括停用档案**。达到上限则清除待触发时间并暂停；解除托管腾出空间或提高上限后，重新抽取未来间隔，不立即追补。
6. 昵称不足等预检失败显示本次原因，保留原档案与运行角色，并在下一随机间隔再尝试；不自动添加数字后缀，也不静默覆盖同名角色。
7. 总开关关闭时暂停新增并取消待触发；重新启用从当前时间重新计时。更改间隔同样重新计时，保存无关设置、查看页面或刷新不会重抽。

新陪玩默认全天可候位，单次最长120分钟、基础休息20分钟、每日及滚动24小时240分钟。可在“随机新增”页编辑默认作息；只影响之后生成的档案，已有角色保持自己的作息、人格和用量。昵称池与“批量新增陪玩”共用，保存前仍使用原确认弹窗，取消不写入。

管理显示当前档案数、下次触发时间、累计自动生成数、上次结果。页面上的全局触发时间按北京时间显示，角色会话/休息时间按角色所设时区显示。下次触发不是下次实际进入游戏的保证，在线名额不足时新角色进入候位队列。

## 20个陪玩、10个在线名额如何轮换

候选首先经过总开关、启用状态、人工下线抑制、错误、职业开放、在线日程、出勤、休息及每日/滚动用量检查。未满足条件的角色不进入可上线队列，不为凑满人数擅自恢复死亡预算停用角色。

- 同一时刻最多占用设置的在线名额，并受原MaxUser、MaxIP、真人预留名额及封禁/登录开关进一步约束。
- 同等可连接条件下，**等待较久者先上**；同一时刻进入队列时，用稳定的个体种子和编号打破平局，不按昵称排序，也不让新角色凭“今日在线0分钟”无限插队。
- 获得名额就清除旧候位时间，下次休息结束重新排到当前队尾。候位时间保存到本版本SQLite，重启不清空等待优势。
- 注册/建角被原限频或注册开关阻挡时跳过该角色，已有账户可以继续补位；不提高原限额或制造GM账户。可连接条件恢复后仍保留原候位时间。
- 不在短周期里随机踢人换座。角色到本次预计截止、窗口/额度结束、被人工下线、被停用或上限缩减时正常退出；名额空出后按原连接节流逐个补位，允许出现短暂空位。
- 上限缩减时，优先让本次预计结束较早的角色退场；保持其他角色当前会话。正常退出期间仍占用一个调度名额，原账户连接和执行组件都确认结束才释放，避免旧人还没退、新人已超额进入。

因此10个角色不会长期固定占座：短玩的先休息，排队中的补位，长玩的继续到自己本次截止，之后同样休息和重排。日程没有足够候选、额度耗尽、原服限频或名额被真人占用时，不强求一直保持10个在线。

## 人格如何影响长短游玩

“智能轮换”默认开启。以勤奋和坚持计算投入度：`(勤奋 + 2 × 坚持) / 3`，再决定本次时长范围：

- 最短比例为角色单次上限的 `20% + 投入度 × 55%`，最长比例为该比例加25个百分点，上限100%。按整数分钟抽取，至少1分钟。
- 懒惰预制（勤奋20、坚持25）的投入度约23，通常在单次上限的32%–57%之间；单次上限120分钟时约38–68分钟。
- 勤奋预制（勤奋90、坚持85）的投入度约86，通常在上限的67%–92%之间；上限120分钟时约80–110分钟。
- 休息以角色基础休息时长乘以人格系数和80%–120%的随机浮动；投入度高的休息较短，低的休息较长。基础休息为0则仍为0，但重新候位不能挤占等候更久者。

这些是调度规则，不修改预制人格标识或修订，也不改变独立保存的十维参数。角色在线窗口、单次上限和剩余每日/滚动用量是硬边界，本次计划取其中更早截止。暂停仍保持连接、计时及用量，到期同样正常下线。

**每次会话只抽一次，并保存开始、截止和本次休息。** 宿主正常重启后，在截止前重连仍沿用本次截止，不能每秒、刷新页面或重启重新抽到更长时间；离线跨过截止会结束旧会话并按原计划休息。管理员改变智能开关只影响之后的新会话，已开始的计划不反复重抽；日程/配额收紧仍立即参与资格判断。手动“启动”和“全部上线”保留原人工恢复语义，不能清除累计用量。

关闭智能轮换后，使用角色固定的单次最长在线和基础休息时长，公平候位、人数/配额及退场保护仍然保留。

## 智能托管

入口：“陪玩设置 → 在线调度 → 智能托管”，默认关闭，不依赖LLM。启用后每30秒巡检健康与待恢复状态，原30秒心跳及20秒控制租约继续有效；心跳失联、工作进程退出/卡死、无未决资产的断线/移动或租约超时可进入恢复。长时间等待安全来源、正常休息或没有经验增长不直接视为进程故障，也不伪造任务进展。

- 技术故障保留档案启用、原run/pause意愿、累计用量、会话截止/休息计划及本次死亡次数；不再一律永久停用。先请求旧会话结束，执行组件确认结束且原账户连接消失后才释放名额。会话停止15秒仍无回执时清理重建执行组件；宿主级管道故障同样清理，仍使用原组件的8秒退出等待及必要时只终止该组件的故障清理，不改变正常轮换的原LogOut流程。
- 每次失败保存下一次恢复时间，按30、60、120、240、480、900秒退避，之后每次最多15分钟；30秒巡检和原连接节流可能再延迟实际重连。连续健康运行5分钟且本会话没有死亡后清零连续恢复次数。重启不重抽退避，也不重置死亡/用量或延长原会话。
- 新连接重新通过原TCP登录，读取原服当前身份、物品、金币和任务，不带入或重发旧未决请求。暂停角色在进入发展循环前即保留pause控制。死亡次数由宿主持久记录，重连通过私有启动信息传回；正常新会话、明确人工启动或经核验的智能死亡恢复开始新预算。
- 对旧版已停用的记录，只精确识别原心跳、工作进程退出、客户端结束和正常下线超时四种技术错误；核对同一账户/角色身份、原连接已退出及死亡时的安全复活点，再恢复到排队。人工下线抑制（即使已过期）、新的人工停用标记、人工pause意愿均不能被旧故障匹配覆盖。没有模糊包含式匹配，也不自动修补未知配置或伪造角色。
- 人工“下线/停用”立即撤销恢复资格；关闭智能托管/总开关暂停自动恢复。已报告的资产/任务/药卷/仓库/退出回执未知、交易、身份/协议/素材校验及存储写入故障仍保护阻断。已死亡但未耗尽预算的确定技术故障须核对原安全复活点，保留原次数重连；预算已耗尽则转死亡恢复队列。不踢占用账户的其他连接、不清封禁、不加额度、不重置角色或发GM物品。
- 新档案死亡预算默认10次。有空位时优先处理到期的技术恢复，再处理精确死亡预算错误；死亡重试2、4、8、15分钟封顶。必须核对原安全复活点可走且在原安全区内、非红名监狱复活、旧TCP已退出，并仍满足作息/休息/额度。上次死亡次数进入原日志与上次会话原因后才重开预算排队；不直接改HP、金币、物品或绑定点。人工下线/停用/暂停不能被恢复，未知错误不以模糊文字匹配清除。
- 进入原服后私有entered回执可能迟于断线；服务端先核对真实角色并保存绑定，只对本角色安排恢复，不再误报为全局“尚未正常进入游戏”阻断。每个新会话仍有独立编号，旧回执不能污染新会话。

列表显示“托管恢复中”、尝试次数、等待原因和下一时间；关闭开关显示“托管已暂停”。兼容能力显示全局阻断及当前待恢复人数。恢复不是立即上线保证：在线上限、真人预留、同IP、日程、休息、出勤及每日/24小时额度仍全部生效。即使所有角色额度耗尽，也不为保持在线人数绕过限制。

持久化只在原schema2封套增加有默认值的托管设置、下一恢复时间/次数、人工阻断和会话死亡计数；旧程序遇未知字段仍拒绝写入，不混用旧运行程序。私有协议11增加可恢复标记和启动死亡计数，宿主/companion/管理端必须配套更新；原游戏TCP和角色/行会资产格式不变。

## 安全退场和可观测性

轮换使用私有`retire`控制：停止新发展操作，等待已发物品/仓库/修理、药卷和移动回执。退出请求尚未发出或已明确拒绝时，继续原药卷/自疗保护；面对最近真实怪物攻击者，退场即优先尝试原单步撤退，不等到低血或先打死可猎杀目标，无可行撤步才近身自卫，避免站着挨打；不重新接取、采集、采购或主动刷怪。发出原LogOut后必须收到LogOutSuccess才关闭TCP，等待结果期间不插入其他动作；写入网络不代表角色已退出。原服明确LogOutFailed时等待至少1秒后再申请，继续遵守原10秒战斗保护；同一退出请求5秒没有回执则停止并提示未知结果，不自动重发。资产未知/拒绝/超时仍按原保护停止并提示，不为腾名额忽略错误，也不超时重发资产请求。退场超过原30秒预算仍未结束时，默认阻断该角色；开启智能托管后可对确定的技术超时按上述退出核对和退避恢复，资产未知等保护仍不解除。没有新增提前回城或专用安全区路线，强敌/持续围攻仍可能无法正常退出；宿主停服、进程故障及强制停止保留原清理路径，不宣称这些都收到正常退出回执。

列表和详情显示候位顺序、本次预计截止、休息至和上次下线原因；顶栏显示候位/休息/退场人数。“日程与在线概览”显示随机新增状态。候位序号不是精确倒计时，可能因窗口/用量、原服限制或人工操作变化。

持久化继续复用`companions/settings.json`及各`companions/profiles/*.json`的现有封套；只增加有默认值的配置/调度状态，不迁移角色或原引擎资产。旧程序对未知字段仍阻断写入，不能混用旧运行程序。当前私有管道版本为`mir2-companion-12`（包含原8的安全退场），服务端、管理端及companion执行组件须配套构建；原游戏TCP包编号/布局不变。

完整切换版本目录会同时切换计时、队列、人格和用量。复制A到B后仍按原实例校验关闭B的总开关；在B明确启用时重新安排随机新增，不使用A逾期事件批量建角。无跨版本共享可写资料，不需要LLM服务。
