# 商城与物品价格

管理端“商城管理”分为“公共商城”和“物品价格”。物品价格表列出当前版本全部物品，支持按名称或编号搜索，显示原素材图标及买价、卖价、回收价，逐行编辑、确认保存；取消不写入。

- 买价：NPC出售给玩家的单件基础金币价，继续乘商人交易倍率和适用的城池税率。
- 卖价：玩家卖给NPC的单件基础金币价。
- 回收价：物品设置允许自动回收时的单件基础金币价。绑定、任务、强化、高品质等原保护不变；未鉴定装备仍须明确勾选回收。
- 三种价格继续应用原数量、耐久、附加属性及魔血石储量修正。毒符基础价按次数，公共商城按整包计算。未配置时保持旧计价及奇数整叠舍入；配置后的卖价、回收价各自独立结算。
- 价格为0表示无对应金币价值；NPC的0买价仍沿用原免费规则，公共商城不允许上架0买价商品。NPC会话、支持类型、距离、绑定、容量、负重与金币上限均继续检查。

公共商城只设置商品倍率，实际售价为“整份基础买价 × 商品倍率”，向上取整。例如买价100、倍率1.1时售价110。商城不再随角色所属行会或NPC税率变化，商品报价在购买时重新核对；改价后旧报价失效。未单独设置倍率的商品持续跟随系统设置的公共商店倍率；单独设置后覆盖系统值，即使数值恰好与当前系统值相同也保留覆盖。新增商品默认跟随，清空倍率恢复跟随。改变系统倍率前检查继承商品是否溢出，保存后旧报价立即失效。

交易价格保存在版本SQLite的`settings/item-prices.json`，不改原ItemInfo或UserItem的二进制字段。原定义Price继续用于修理等非买卖计算，开发页面不再编辑它。价格管理写入通过游戏线程与AdminChanges，保留完整SQLite备份、读取版本检查和事务失败回滚；服务端成功提交后向已声明价格同步能力的在线微端和陪玩发送追加包。原有包编号及字段布局不变，新包只发给主动请求的新客户端。

商城快照升级至Schema 3，PriceRate为null表示继承系统倍率。Schema 2的数字继续保留为显式覆盖，不根据数值相等猜测用户意图。Schema 1的显式绝对价按对应基础买价换算倍率，向下保留12位以避免多收1金币；未指定单价时持续继承系统默认倍率，原号角100万的默认值换算成商品倍率。没有基础买价的旧绝对价商品使用1作为转换基数，卖价、回收价保持0。读取转换不写数据库；保存商城或物品价格时，在同一事务保存转换后的货架和价格，避免重启重新按旧价换算。未知格式保留并拒绝加载。升级前须备份数据库；Schema 3写入后不能仅降级程序继续写库。

验证入口：`--item-price-checks`覆盖三价、耐久、奇数默认、价格协议归约、原包布局、旧商城转换、SQLite恢复及提交失败回滚；`MIR2_PRICE_UI=1 python3 tests/Management/item-prices.py`覆盖隔离原TCP买卖/回收/重放/倍率实扣、浏览器及完整重启。须在独立源码副本构建运行，测试只读复用原素材。

`MIR2_OPERATIONS=1 MIR2_PRICE_UI=1 python3 tests/Management/item-prices.py`追加金币共享/越界/冲突/失败回滚、重启预保存故障、12个真实TCP陪玩与并发重启恢复、在线分页，以及按钮实际高度/资源下载样式/地图最大1:1及布点检查。
