# 怪物属性与掉落管理

“刷怪管理 → 怪物列表”打开当前版本全部怪物，服务端每页50条。卡片保持瀑布流，纵向长条布局，上方原图，下方编号/名称及等级、生命、攻击、防御、魔御和基础经验；分页居中；点击卡片打开“属性 / 掉落”弹窗。刷怪点的“查找怪物”使用同一图鉴，点“选择”回填原编号。

## 刷怪地图

刷怪范围按逻辑格半径计算：到中心的平方距离不大于半径平方，角落超半径的格子不再进入候选。热更新、重启和陪玩只读来源共用`Map.GetRespawnCells`；阻挡中心与管理预览共用`Shared.RespawnArea`最近可走格修正，不改已保存的布点坐标。地图仍按原48×32格距呈现，因此逻辑圆投影为扁圆；不能为画成屏幕正圆拉伸底图或扩大纵向范围。浅色范围的半径与地图同比缩放；阻挡格、地图边界仍由原引擎过滤，范围不是所有像素都能生成。

已保存及未保存标记用名称首个完整Unicode字符加数量，数量字号为名称的80%；悬停显示完整名称、数量、原坐标/半径及修正后的实际中心。只在标记文字上选择编辑，范围内部仍可点击新布点，保留键盘Enter/空格和多点草稿保护。范围0只在有效中心生成，不绘制范围圆。圆形候选会减少原方形四角的刷怪位置，但不改数量、刷新间隔或怪物定义。

## 属性

可编辑名称、等级、基础经验、外观/行为/特效、视野/识破隐身/光照、攻击/移动间隔、完整原战斗属性以及首领/不死系/诱惑/推动/召回/显血/出生和死亡脚本开关。编号固定；“添加其他属性”可编辑原本为零的原引擎属性，不维护第二份战斗计算。

底部“保存”先弹窗确认，再通过受版本绑定的管理API和游戏线程提交；沿用SQLite快照备份/事务、失败内存恢复，完成后正常保存在线数据并重启游戏引擎，使外观、AI及已有怪物同步更新，客户端需重新连接。修改名称时固定原默认掉落脚本引用；按名称引用怪物的任务/NPC等脚本仍须运营者同步核对，不自动全文替换。

## 组合掉落与公共目录

掉落页不再区分“共用/独立”模式，也不展示关联怪物。选择多个公共TXT，上方按目录或空格分隔的多关键词查找、逐项移除；编辑框只保存怪物自身规则，下方自动显示服务端解析的最终掉落。草稿错误或预览未完成时不能保存，异步旧预览不会覆盖新草稿。最终预览统一使用百分比、四舍五入保留3位小数；极低正概率显示为`<0.001%`。此格式仅展示，不回写原规则或改变实际判定。

```text
最终掉落 = 所选公共脚本 + 怪物自身规则
```

同一层、同一物品编号、相同任务限定与类型的普通条目合并：基础概率相加并封顶100%，数量相加。例如 `10% 金创药(小量)` 与 `20% 金创药(小量) 2` 合并为 `30% 金创药(小量) 3`。单条及合并数量上限100；金币的基础额相加，上限一亿，再走原金币浮动。Q与普通条目不混合，GROUP/GROUP*/GROUP^完整保留内部顺序和条件，不跨分组合并；GROUP*仍只随机取1份。这是用户要求的新产出语义，**不等同于原重复条目分别独立判定的分布或期望产出**。

普通条目支持原 `1/N` 或精确十进制百分比，数量是可选数字、省略默认1；明确COUNT=仍可读取。示例：

```text
1/100 金创药(小量) 2
10% 金创药(小量)
0.05% 稀有物品名称
1/5 任务物品名称 Q
1/10 Gold 100
```

百分比必须大于0且不高于100%；最终预览显示掉落倍率及角色/稀有度加成前的基础规则。未合并的原1/N条目保留原判定算法；新百分比及合并条目用精确概率分支应用原倍率和掉率加成，再走原物品生成、任务校验、归属和拾取。钓鱼、觉醒、宝箱、黑石和龙兽专用文件不参与此次怪物组合；龙兽第三列仍是等级。

配置继续保存在版本内原TXT与MonsterInfo.DropPath，不增加数据库表或世界存档字段。公共库仅保留通用程度高的金币、生命/魔法恢复药及回城/随机卷；装备、技能书、任务物品、材料、其他特殊药品和完整随机分组放在怪物自身规则。按“金币＋补给”生成，每种怪物最多2份默认公共脚本。整理时先统计不同怪物定义编号，只有至少3种怪物使用的内容才保留为公共；只被1–2种使用的完整合回各怪物自身，公共文件移除。单纯组合整理不新增物品；下述基础补给平衡入口才主动为全部怪物补充基础物资。管理页仍允许运营者手动多选。

```text
world/Envir/Drops/
  公共/金币/金币1500-50.txt
  公共/补给/基础补给.txt
  怪物规则/怪物-编号.txt
  系统/钓鱼00.txt
  系统/觉醒.txt
  系统/宝箱.txt
  系统/黑石.txt
  系统/龙兽.txt
```

公共路径固定为“公共/分类/文件名”3级，不再有通用组合、装备套装或额外的基础金币子目录。文件名中的金额、数量、基率等数字使用阿拉伯数字，文字用中文，不用备用/分类流水号；同名不同补给用实际内容、数量和基率区分。**仅统一概率添加数字后缀：百分比四舍五入到整数（1.111…→1、1.666…→2）；低于1%仍用0；混合概率不加数字后缀。取整只作用于文件名，正文与实际判定保留精确概率。** 专用系统脚本移出公共库，不出现在公共选择器中；NPC DROP专用奖励保留在事件目录，不能塞给无关怪物或误删。

怪物规则文件使用版本标记和明确分隔：

```text
; MIR2-DROP-COMPOSE 1
#INSERT [公共/补给/基础补给-10.txt]
; MIR2-MONSTER-RULES
1/100 怪物专属物品
```

管理编辑框无需填写INSERT或这些标记，公共依赖统一由选择器管理；不允许选其他怪物自身规则、专用系统脚本或重复选择同一文件。最多256个选择、512份依赖、16层引用、展开10000行，检查循环、路径越界/嵌套符号链接、真实物品、数量、金币和分组。保存前分别核对怪物基线版本、草稿预览及全部依赖哈希，防止新选公共文件在预览后改变。保存仍走Changes、文本备份/原子替换和SQLite事务；失败恢复文件/DropPath/运行规则，成功当前怪物即时生效。未实现文件与SQLite跨断电的原子提交。

公共脚本需要整体编辑时，继续使用“游戏开发 → 脚本与配置”，然后重载掉落使全部引用者加载。文件读取不创建目录或文件；首次建库才从import补充Configs/Envir，已建库重启不复活删除或改名的旧脚本。

## 拆分组合已有脚本

正常保存并退出宿主后，用所选版本及配套程序执行：

```sh
MIR2_DATA_ROOT="$PWD/data/versions/default" dotnet src/Server/bin/Release/net8.0/Mir2.Server.dll --compose-drop-scripts --check
MIR2_DATA_ROOT="$PWD/data/versions/default" dotnet src/Server/bin/Release/net8.0/Mir2.Server.dll --compose-drop-scripts
```

入口受版本独占锁保护；预检不写入，实际执行先备份SQLite与world，再原子替换文件并在世界事务中更新引用，失败恢复。对已组合版本也可重新整理成基础公共库：逐怪物读取当前最终规则，只抽出金币及普通补给，按内容复用相同公共文件，其他规则完整写回本怪物；不从目录旧模板推断或新增物品。未使用的旧公共模板及装备/材料公共文件从活动库移除，完整原文保留在本轮备份。按物品编号而非输入顺序规范生成，重复执行无写入，不因不稳定排序反复改名。

每个怪物重新解析，与整理前最终规则逐项比较概率、数量、金币、Q/类型和分组；系统文件原文及专用等级/判定不变，Setup.ini同步系统路径，NPC DROP单独同步。基础公共库整理不再次叠加已经合并的数量或概率。

报告在所选版本runtime/backups/drop-scripts-*。只有怪物引用变化才提交世界定义，纯文本整理不重写任何SQLite快照；不改账户、角色、行会或陪玩快照；正式应用前后另核对这些快照和SQLite完整性。重复组合执行不重抽规则、不重复叠加；已组合版本拒绝旧`--organize-drop-scripts`入口，避免旧整理重写组合标记。

## 基础补给与通用装备

`--balance-supplies [--check]`复用上述停服独占锁、预检、文件恢复和世界事务，按当前版本实际等级及基础生命重建全部怪物的普通金币/恢复药规则，再整理成公共组合；不叠加旧普通金币和恢复药。任务限定Q、装备、材料及其他特殊规则保留。基础金币及每种药品各独立50%，药品每次1份；按掉落倍率1设置，不除以10，经验倍率独立。角色/稀有度加成、禁止掉落地图及特殊怪物原死亡条件仍生效，金币继续走原数量浮动，不保证每次恰好等于档次基础额。

| 怪物等级及基础生命均不高于 | 基础金币 | 恢复药 |
| --- | ---: | --- |
| 10级 / 50生命 | 100 | 小红、小蓝（658/659） |
| 20级 / 150生命 | 200 | 中红、中蓝（660/661） |
| 30级 / 500生命 | 500 | 大红、大蓝（662/663） |
| 40级 / 2000生命 | 1000 | 特大红、特大蓝（664/665） |
| 50级 / 10000生命 | 2000 | 瞬回红、瞬回蓝（666/667） |
| 65级 / 50000生命 | 5000 | 疗伤药（生命/魔力各300） |
| 超出以上范围 | 10000 | 万年雪霜（生命/魔力各500） |

等级或生命任一超界即进入更高档。疗伤药/万年雪霜若不存在，沿用当前版本原瞬回药定义新增物品，保留原使用包、生成与拾取规则，不向玩家发放资产。default首次应用前已只读核对分组内没有待替换基础物资，因此本次没有因删除分组子项改变其他分组的选择概率；其他版本仍需先核对预检报告。

采集型怪物的普通根金币及恢复药改为死亡落地，尸体割取排除这些已落地条目；原肉类、任务采集及分组语义保持。分组中的金币仍不会由原Harvest发放，也不能当作陪玩筹资来源。

同一入口将原多职业装备（至少两位职业标记）改为全五职业31，单职业装备、技能书与其他身份要求保持；微端详情隐藏全职业要求行。default已修改119件定义，现有物品编号和实例不变。正式基础规则覆盖555种怪物，七档数量为50/46/75/76/124/136/48；短时验证不代表所有特殊AI、多日经济和全部任务都通过。

## 卡片与验证

管理端 `app.css` URL使用框架内容哈希，避免旧无版本缓存导致卡片丢样式。浏览器回归同时检查多列瀑布流、图下名称、子目录筛选、嵌套编辑/确认取消及旧缓存场景。

`--monster-drop-checks`检查概率/数量相加、封顶、实际抽样、任务/分组/INSERT、管理校验、预览后依赖冲突、属性边界及提交失败恢复；`--drop-composition-checks`检查完整拆分组合、概率四舍五入/混合无后缀/低于1%、3级目录/阿拉伯数字、最多2份基础公共/其余自身、旧公共清理、NPC引用、只读预检、失败回滚及幂等；`--drop-organization-checks`使用独立临时版本检查公共引用、中文路径、清理、特殊龙兽等级、NPC/INSERT重写、只读预检、幂等、SQLite失败完整恢复与玩家/行会/陪玩标记不变。

`MIR2_MONSTER_UI=1 bash tests/Management/ui.sh`验证怪物目标界面和正常重启；不带该开关的 `ui.sh`覆盖完整管理端。目标UI回归还会在同一临时版本正常退出并连续启动完整宿主两次，核对旧导入掉落不复活、保存和SQLite完整性。测试不对default写入测试怪物或脚本。整理前后有效规则逐项相同不能替代长期经济或全任务实测。

`python3 tests/Management/drop-combat.py`在独立临时版本通过原TCP验证击杀/经验、多脚本合并后6件装备逐件生成原唯一编号并实际拾取；不把任务奖励或管理发放当作掉落证明。

怪物编辑内容区保持稳定高度，页签内容在内部滚动，加载进度不撑开弹窗；浏览器逐帧检查先等待打开弹窗的正常缩放动画结束，再验证属性/掉落切换与异步读取阶段高度、位置不跳变。
