# 后续完善顺序

当前可验证的闭环是 macOS 上的原 C# 游戏引擎、SQLite、Godot 原生微端和独立 Blazor 管理台。继续扩展以原客户端和原协议为依据，每次补齐服务端规则、客户端表现和必要的管理检查，再运行隔离回归。

## 已有基线（2026-11-11）

- 微端：注册/改密/选角、移动与寻路、基础战斗/技能、装备/背包、NPC 商店、任务、共享仓库/密码和扩展页、死亡复活、聊天、组队、原协议双人交易、行会信息/公告/成员/职位和资源缓存恢复。
- 服务端：原规则与 TCP、SQLite 世界/玩家/行会及交易托管快照、完整备份、游戏线程管理命令、统一资源版本、组队接收权限复查、发送顺序/部分写入和慢客户端积压保护。
- 管理台：监控及在线队伍/交易信息、账户/角色/行会、刷怪管理多点事务/怪物形象弹窗及阻挡落点自动修正、独立 NPC 原尺寸大地图/小地图与属性/脚本弹窗、资源类型筛选及分页图片瀑布流、1024 像素地图缩略图重建、文本/基础定义开发、版本冲突保护、受保护账户删除与统一 CRUD 弹窗；资源暂存/发布保留受保护 API，界面入口已移除。
- 管理交互：刷怪创建/管理共用表单，编号旁弹窗选怪，地图名称紧凑；取消手工目标输入并保留自动名称匹配/保存删除确认。怪物图鉴与选择器统一 4:6 分栏、明显分割线与属性双列；NPC 瀑布流卡片可“查看”所属地图并定位，同图和重复定位已覆盖浏览器回归。
- 发布与版本：build/server、build/admin、build/client 三端程序；data/versions/default 为当前版本，完整目录复制后独立运行；服务端/管理端版本目录配置、错配保护、源码目录外部署及发布微端完整游玩/重启已验证，见 DEPLOYMENT.md。
- 已有测试覆盖原生 Godot 游玩和组队、SQLite 重启及缓存损坏恢复、管理 API/事务失败回滚、三个启动脚本与隔离登录。本地回归不代表长期多人线上稳定性。

微端界面、原协议和渲染的对照结果见 [客户端对照检查](CLIENT_PARITY.md)。

2. 行会信息/公告/成员/职位及仓库/资金已形成原协议闭环，覆盖邀请/拒绝、招收/移除、权限、会聊、离会、112 格存取/交换、成员捐献/会长取款和重启恢复。原NPC建会命名及宣战输入、原金币/材料扣取与拒绝、敌我颜色、攻击模式/安全区与定时结束已完成真实Godot/TCP专项，详情见CLIENT_PARITY.md；原战争关系不跨完整重启保存。账户与行会快照同一 SQLite 事务保存，写失败一起回滚；仍未逐笔即时落盘。增益、领地及完整攻城继续分步接入。

## 陪玩（假人）系统：规则与管理已接入

当前功能及限制见 [陪玩管理与运行](COMPANIONS_OPERATIONS.md)。管理台已支持资料、人格式样与不可变修订、时区日程、配额、启停和错误详情；独立 .NET 组件通过原 TCP 创建和发展角色，规则无需 LLM。持久数据位于版本 SQLite，目录复制后默认关闭自动运行，协议指纹不匹配阻断。

已支持基础打怪/拾取/换装/补给/修理、服务器任务/掉落目标引导、公开入口跨图收集并返回交付、组队与有限聊天、自卫/显式约战，可选模型增强。无进度保持在线等待重新规划。后续重点为复杂脚本/特殊条件入口、掉落收益/装备目标分析、长期记忆、邮件/玩家交易资产恢复和规模/弱网压力；不把总体设计视为全部验收完成。

default 当前以10倍经验持续实玩；普通房屋出口、开门、跨平台掉落子目录、送物/纯拜访、尸体采集、普通肉出售及商人修理类型预检已接入。任务/掉落来源检查、原版功能缺口及每30分钟迭代交接见[持续游玩记录](COMPANIONS_LIVE_TEST.md)。优先修复零金币无武器恢复、脚本标记与缺失NPC关联，扩大全职业/限级任务覆盖，再逐个补齐邮件、寄售及特殊锻造等完整交互。
