# 陪玩行会发展与攻城

## 管理入口

在“陪玩管理 → 管理 → 行会与攻城”设置单个角色；“批量新增陪玩”使用相同字段。保存沿用版本检查、确认弹窗、事务和取消保护。详情中的“行会 / 行会发展”显示原服会籍和当前计划，最近事件显示申请、邀请、建会与入会回执。

| 设置 | 行为 |
| --- | --- |
| 关闭 | 默认值，不主动建会、申请、招收或参与攻城；已有会籍保留 |
| 主动入会 | 寻找有名额、未处于禁止招收战争状态且有在线招收人员的行会，主动申请并接受匹配邀请 |
| 自主建会 | 达到当前版本原建会条件后前往实际建会 NPC；已有会籍时正常发展，不退出重建 |
| 自动发展：分阵营建会与入会 | 未指定名称时按稳定档案编号分三股发展，优先本阵营可招收行会；本阵营尚无行会且条件满足时分别筹备建会，不再全部加入首会 |
| 目标行会 / 拟建名称 | 留空自动选择，自动建会名为角色名截取后加“同盟”；填写时严格匹配目标名称，建会也使用该名称 |
| 参与本行会攻城 | 独立勾选，另须开启“陪玩设置 → 允许 PK”；会长可向原 NPC 报名申请制城池、会聊集结，成员按本会资格赶赴原战区 |

名称为空或 3–20 个字符，不能含控制字符、反斜杠或首尾空白；实际创建仍受原服命名、重名及保留名称规则检查。自动生成名并不保证未被占用；冲突时显示原因，需调整名称或选择入会策略。

新字段默认关闭，升级现有档案不会自动建会或花钱。无需 LLM；人格、补给、作息、死亡预算和原在线容量继续生效。关闭策略或攻城勾选只停止后续计划，不自动退会或撤销已经由原服确认的操作。

## 建会闭环与费用

1. 服务器只读当前版本真实等级、金币和材料要求。与原 `PlayerObject.CreateGuild` 共用 `GuildCreationRules` 预检，保留跨堆叠和原矿石纯度判断，预检不扣资产。
2. 同组已达等级、启用且无错误保护的正常游玩档案选一名筹建候选：以原引擎当前玩家名单确认在线，包含日程自动上线、手动启动字段仍为off的角色；人工暂停、下线抑制、休息及已到期退场排除。先已有材料，再按金币与稳定编号排序，离线档案不阻塞在线筹备。候选按真实货架计算“缺少材料价＋两倍建会金币费”，先低风险打怪拾金筹足，再从原商城购买缺少的普通建会材料，最后走原 NPC 建会。药品、减负、修理和已齐交付优先；筹资期间暂停鉴定、购装和新魔血石等非必要消费。default 建会费100万、沃玛角100万，需先积累300万，买角后仍有200万，建会后保留100万。商城缺货、特殊纯度材料或无安全来源时等待正常发展/重试，不补金币或材料。
3. 根据当前地图编号和公开步行出口寻找包含原建会页面的实际 NPC。建会赶路优先于闲时打怪、拾取、临时访商和跟队，并保留补给、减负、真实交付及低血撤离。到达后读取当前对话链接。页面暂不可用时排除该目标并重新规划。
4. 通过原 NPC 调用取得命名请求，再发送原 `GuildNameReturn`；名称、地图、NPC 和提示有效期必须匹配。金币扣除、材料移除和建会均由原引擎执行。
5. 等待同名 `GuildStatus` 回执后才记录成功。未知结果停止且不自动重发；重新启动前通过原角色资产及会籍核对。

同一发展组只安排一名当前筹建发起者，降低同时竞争。建会材料不进入自动回收/存仓清单；执行端按实际持有量复核，旧规划不会重复买角。筹资在原风险筛选后按正常掉金均值、普攻与近似路程排序，不改变掉落或承诺全路安全。自主建会模式的其他角色在已有创建者完成后仍可另建自己的会；若希望大家加入同一个会，应统一填写行会名称，并将其余角色设为“主动入会”或自动策略。

自动阵营不另存一份会籍，沿用档案稳定编号及原行会会长身份判断；重启、会长离线或在线人数变化不重分已有成员。有名额但暂不可招收时等待本阵营会长上线或战争结束，不重复花钱建会；满员时可继续筹备新会。指定名称、仅入会、自主建会和关闭策略继续按原意执行，已有会籍不强制拆散。未识别为陪玩会长的普通行会仍可按原自动/指定规则选择，候选行会内按人数与稳定编号比较。

推荐配置：一名资金和等级充足的角色设“自主建会”，其余角色设“主动入会”，统一名称。缺条件、没有公开可达建会 NPC 或重名时详情解释原因，继续普通任务/补给，不使用 GM 补钱、补物或传送。

## 主动申请与招收

- 自动选择时先按阵营和目标名称筛选，优先有在线陪玩招收人员的行会，再比较人数与稳定行会编号；指定名称时不会改投其他行会。
- 开启原服行会邀请开关，启用聊天时向有招收权限的在线成员私聊申请。同一角色申请节流为 10 分钟；真人会长仍需自己决定是否邀请。
- 有招收权限且开启行会发展的陪玩，按服务器计划邀请已启用、具有运行意愿、配置入会/自动策略且接受邀请的陪玩，使用原 `EditGuildMember`；邀请节流 20 秒。不自动邀请任意真人。
- 申请者只接受与当前计划名称相同的原邀请。招收权限、战争状态、名额和重复邀请由原服再次验证；不会直接修改成员表。
- 已经有行会的角色继续在本会发展，不自动退会、踢人、改职位或合并行会。行会经验等收益仍来自原引擎正常行为，没有额外发放。

## 攻城与驻守

服务器读取当前版本 `ConquestInfo`、实际战争状态和会籍。Request 制只规划本会作为原守方或指定攻方的战争；其他类型保留原引擎的领地资格限制。无资格、未加入行会或任一开关关闭时不接管行会作战。

- 会长及至少一名本会陪玩实际在线、正常游玩并同意攻城时，会长可前往有真实 `SIEGE` 页许可的 NPC，逐级读取当前链接后报名；日程自动上线与手动启动同样有效，保留人工暂停、下线抑制及错误保护。普通成员、已占城行会、本城守方、友会、已占用报名位、无战期或非申请制均被原服复核阻断；不覆盖其他攻方，不调用 `STARTCONQUEST` 强制开战。原 `SCHEDULECONQUEST` 动作与报名页共用资格及存档标记。
- `POST /management/development/sieges/prepare` 幂等安装盟重“司戎长老 / 攻城报名”，经原定义备份提交并正常重载；已有不匹配脚本拒绝覆盖，不修改城池战期/类型/费用。报名沿原 `ScheduleConquest` 的无额外费用规则，不新造收费。
- 收到原 NPC 明确回执后才记报名成功，未知5秒停止且不重发；原 `AttackerID` 随城池快照保存。会长通过原行会频道发布准备及集结信息；战前15分钟内按公开路线集结，开战后成员执行本会合法目标。`Envir.Now` 是UTC；default原战期18:00–18:30 UTC，相当于北京时间每天02:00–02:30。

- 王宫占领与经典模式都公开步行前往实际王宫：经典模式由原引擎统计王宫内人员决定归属，不把山丘坐标当成王宫。山丘/控制点则按原计分区域选择落点；路径及落点均来自当前版本地图，不写死沙巴克名称、地图号或坐标。
- 驻守避开被占用格和公开切图出口，必须实际走到服务器选定的有效格；已在有效计分范围内时原地驻守，避免所有成员挤向同一中心。中心受阻时有界检查完整四边，不能选到计分范围外；搜索预算为中心32格内，已在更大合法范围内的角色不受该搜索预算限制。没有有效格时等待重新规划，不伪装成占领成功。
- 切换原“行会模式”后，攻击服务器筛选的当前战区敌对行会成员、敌方城门或城墙。每次规划都核对陪玩和目标是否同处实际战区，目标离开后在下一次引导刷新移除；原引导约3秒同步，不能承诺移动后零延迟停止。排除友会，继续遵守原 `IsAttackTarget`、安全区与禁战判断，执行仍发原战斗包。
- 到达目标驻守；占领和城池归属由原引擎判定，不能把“正在攻城”文案当作实际占领。
- 药卷保护、自疗、未决资产、死亡预算、减负/补给/修理及已完成任务交付仍优先；原地图入口或脚本不允许通行时不绕过。
- 战争结束后重新规划正常发展，普通社交/PK逻辑恢复攻击模式。没有普通行会自动宣战、付费报名、攻城器械、复活集结、多人阵型或复杂战术。

## 版本与验证边界

策略保存在所选版本 SQLite 的原陪玩档案封套中，实际会籍、资金及城池继续保存在原引擎快照。完整切换版本目录时一并切换。当前私有协议为 `mir2-companion-19`，材料目标数量/金币预留及报名/集结语义须配套更新宿主和执行组件；原游戏 TCP 和行会快照不变。

## 可选模型抉择

增强模式“社交、行会与候选决策”下，仅有两个以上当前合法选项时，模型可选择筹备建会、申请候选行会、暂缓，或参与本会已有资格的战争/继续发育。输入为真实等级、生命/魔法、金币、武器、建会费用及候选行会人数，不发送密码/密钥/管理备注。建会和入会等至多6秒短决策期，期间继续接收与保命；拒绝、超时、缺模型/额度或关闭增强后回到规则。结果最多保留10分钟，身份、权限或候选改变后重新校验；招募端同步尊重申请者的有效选择，不反复邀请暂缓入会者。

普通PK仍须设置为限时切磋，并收到附近玩家明确点名挑战；模型可接受或拒绝本次30秒切磋，不会自行选择任意玩家开杀。拒绝在调用间隔内保持，旧会话、低血、死亡、安全区、禁战、队伍及PK关闭时不采用旧接受建议。模型只可在已通过规则预检的报名/集结/参战与正常发展间选择，不能越权改会籍或操作行会资产。所有决策与原有闲时/任务建议共用5分钟宿主间隔、单个决策并发及版本日额度；行会/任务同上下文15分钟不重复，失败沿原模型退避。关闭模型仍可独立筹资、多行会发展、招募、报名组织及按原资格参战。
